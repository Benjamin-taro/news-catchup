# 問いリスト（いま答えを持っていない問いと、今の見立て）

このリポジトリで Claude と話すときの出発点。`/question Q1` か「Q1 について、最近の記事で見立てはどう動くか」と聞くと、
Claude が候補ログ・Digest・wiki から関係する記事を引き、見立てを支持するものと揺らすものに分けて出す。

- 問いは月単位でしか変わらない想定。見立てが変わったら、この場で「見立て」の行を直し、「更新」の日付を書き換える。履歴は git が持つ。
- ID（Q1, Q2 …）は振り直さない。使わなくなった問いは「## 終わった問い」に移す。
- 「揺らぐとしたら」は、どんな事実が出たら見立てを変えるかを 1 行で。これがないと、支持と反証の区別がつかない。
- 「集める経路」は、その問いに関わる記事がいまの網（`interests.md` と `_system/matcha/config.yaml`）に入ってくるかの確認欄。「なし」なら検索語を足す。
- Claude はこのファイルを読むだけで、書き換えるのは読み手が頼んだときだけ。
- 注意：このリポジトリは Public。ここに書いた見立ても公開される。

## Q1. この先も必要とされるソフトウェアエンジニアは、何を持っている人か
<!-- 旧 Q1「インフラとフロントのどちらを深めるか」を、この問いの一部として統合した（2026-10-21） -->
- 見立て：実際にコードを書くスキルっていうものは消滅する、必要なくなる気がする。もっと大局観で見れる人。コードの構造だったり汎用クラスに切り分けるだったり、経験がものをいうみたいなところが人間の手でしかできない気がする（ちょっと矛盾している気がするけど）からそういう書いてもらったコードを人間が扱いやすいようにリファクタリングしたりレビューしたりはたまた元々の設計スタートを構想したりするような人間な気がする。
- 揺らぐとしたら：「残る」とされたスキル（設計・レビュー・運用判断・要件の切り分け）が自動化された実例。逆に、意外な領域で人の採用が増えているデータ
- 集める経路：interests「AI と開発者の働き方」「FDE／キャリア」「Platform Engineering / CI/CD」「Kubernetes / OpenShift」
- 更新：2026-10-21

## Q3. AI で開発職の仕事は数年でどう変わるか
- 見立て：プログラマーみたいなコードを書くだけの人は絶対に消滅。AIを絡めて何ができるか。複数運用ですごい速度の仕事とかバリューが出せる人が重宝される？逆に技術系の知識はあまり重宝されなくなる？意外ともう技術職と総合職の垣根みたいなのが無くなってくる？
- 揺らぐとしたら：採用・レイオフの数字が「人数減」ではなく「職種の消滅」を示す。非技術職が AI で開発を担うようになった実例（垣根が消える側）、逆に技術の専門知識を持つ人の採用・待遇が強まったデータ（垣根が残る側）
- 集める経路：interests「AI がエンジニアの働き方・開発のしかたをどう変えるか」「FDE／キャリア」「AI が書いたコードのレビュー・品質」
- 更新：2026-10-21

## Q4. 銀行の開発は、ベンダー丸投げから内製と AI へ本当に移るのか
<!-- 候補「今の銀行業界における IT 系のトレンド」「金融業界の開発のあり方の変遷と進化」をまとめた -->
- 見立て：セキュリティーなどの観点でも中に入ってきそう。自社のAIとかでナショナリズムではにけどそれぞれ会社独自のエコシステムを進化させていくみたいな展望かな。
- 揺らぐとしたら：大手行・地銀の内製化の数字、または内製からの撤退。自社モデル・独自基盤ではなくベンダー製の AI や共通基盤に寄せる動きが主流になった例。基幹系に近い領域で AI が本番に入った事例、または PoC 止まりの報告
- 集める経路：interests「AI の企業導入（銀行・金融）」「銀行業界の行方を経営の視点で」「金融 × テクノロジーの全体像」
- 更新：2026-10-21

## Q5. FDE は職種として定着するか、一時的な呼び名か
- 見立て：コンサルもバズワードだったみたいにしばらくは残り続けるだろうけど質の担保みたいなものを重要そう。コンサルに技術の知識が入っているような人なのか、それとも技術畑でコンサルみたいな能力があるのかでもその人の有用性みたいなものが変わりそう。
- 揺らぐとしたら：FDE 求人の減少、既存職種（SE・コンサル・SA）への吸収。逆に、FDE の専門組織・資格・品質基準・キャリアパスができる動き。「技術出身か、コンサル出身か」で成果が違うことを示すデータ
- 集める経路：interests「Forward Deployed Engineer／エンジニアのキャリア・組織論」
- 更新：2026-10-21

## Q6. 自動運転は、日本の自分の生活圏にいつ・どの形で入ってくるか
- 見立て：実証実験ができているアメリカとか中国からタクシーレベルで進展している。そこにウーブンシティみたいな完全に自動運転の車しか走っていない世界を構想して訓練しているような世界がどう入り込めるかみたいな感じなのだろうか。あとは重大な事件が一個起きてから改めて倫理の問題とかが普及の速さを左右しそう。
- 揺らぐとしたら：日本の公道での商用運行の開始・拡大、またはその延期・撤退。重大事故のあとに規制や世論が動いた実例。Woven City のような閉じた環境の成果が公道に移植された例
- 集める経路：interests「自動運転」（海外中心。日本の動きは Google News の `自動運転` で拾えているか要確認）
- 更新：2026-10-21

## Q7. 個人開発と業務開発で、AI の使い方はどう分かれていくか
- 見立て：開発とももうよばれないもはやワードとかエクセルみたいなツールになっちゃうのかもしれない。そうなる情報管理に厳しい会社より開発という観点で行くと個人開発の方が自由に色々な活用法が模索されていくかもしれない。
- 揺らぐとしたら：業務側で個人開発と同じ自由度（エージェントに権限を渡す等）が許された例、または業務側で禁止・制限が広がった例
- 集める経路：interests「Claude / Claude Code の新機能と活用方法」「AI エージェントの安全性・権限管理」
- 更新：2026-10-21
