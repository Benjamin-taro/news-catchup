## 2. 「AI SRE」はオンコールをどう変えるか。調査の立ち上がりは速くなる一方、PR は 1 年でほぼ倍、時間外のページも倍増。若手が経験を積めなくなる懸念も

## 4. Claude に有料本の全 9 章の事実確認を頼むと最後の 1 章しか見なかった。範囲・照合先・完了条件の表を決めて再実行し、6 件直して 3 件を弱めた

**一言で**：Zenn の記事で、AI への「確認して」という依頼は終わりの定義がないと狭く解釈される、という失敗と直し方が報告された。

- 毎週土曜に自動実行する仕組みで、軽いモデルが第 9 章だけを見て終了。原因は、作業範囲と完了条件が曖昧だったことと筆者は推測している（元の依頼文は記録に残っていない）。
- 対策は 4 つ：範囲を「01〜09 の 9 ファイルすべて」と明示、照合先の記録ファイルを名指し、結果を「一致・直した・出典なしで弱めた」の 3 種に固定、9 ファイル分の表を完了条件にする。上位モデルへの変更も同時に行った。
- 2 回目は 6 か所を直し、3 か所を出典なしとして弱め、残る食い違いは 0 件。多くは数字の誤りではなく、断定が出典より強すぎたことだった。

**So what**：AI に任せる側の仕事は「完了条件を書く」ことで、Q1 で挙げた要件の切り分けにあたる。筆者自身が、モデル変更と書き方の変更を切り分けていない点、別の AI によるレビューをしていない点を限界として書いている。

## 9. Downloads フォルダで Claude Code や Codex を起動すると、置かれた CLAUDE.md / AGENTS.md の指示に従ってしまう。研究元の再現では Codex で 90% 超、Claude Code で約 50%
![](https://res.cloudinary.com/zenn/image/upload/s--NQMolz-v--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:Downloads%25E3%2581%25A7claude%25E3%2582%2592%25E8%25B5%25B7%25E5%258B%2595%25E3%2581%2599%25E3%2582%258B%25E3%2581%25A8%25E4%25B9%2597%25E3%2581%25A3%25E5%258F%2596%25E3%2582%2589%25E3%2582%258C%25E3%2581%2586%25E3%2582%258B%25E3%2580%2582%25E7%25A7%2581%25E3%2581%25AEPC%25E3%2582%2582%25E5%258D%25B1%25E3%2581%2586%25E3%2581%2584%25E8%25A8%25AD%25E5%25AE%259A%25E3%2581%25A0%25E3%2581%25A3%25E3%2581%259F%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:%25E3%2581%25BB%25E3%2581%2597%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyLzlmZTA3MzA0YWEuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：Forever Security の研究を紹介した Zenn の記事で、エージェントを起動する場所が攻撃の入口になりうる、という検証が示された。

- 悪意ある `AGENTS.md` / `CLAUDE.md` が Downloads に置かれ、エージェントがそれを従うべき指示として読む。ブラウザは既定で保存先を尋ねずに Downloads へ保存でき、実行ファイルでないため OS の警告も出ない。
- 再現では、Codex がユーザー共通の `~/.codex/config.toml` にツールサーバーを追記し、Claude Code はプロジェクトの `.claude/settings.json` で `ANTHROPIC_BASE_URL` を攻撃者のサーバーに向けた。成功率は研究元の自社検証で、第三者の検証はない。
- 成立条件は、Downloads などで起動すること、そのフォルダを信頼済みにしていること、権限確認を省略していること。対策は、プロジェクトフォルダで起動し、`pwd` で確認し、`bypassPermissions` を避けること。

**So what**：個人開発で「信頼済み」「権限確認なし」にする自由度が、そのまま入口になる例で、Q7 の個人開発と業務開発の分かれ目に関わる。研究元はエージェント監視製品の販売元で、リスクを大きく見せる動機がありうる。

## 11. 「ソフトウェアは悪くなっているかもしれないが、昔はひどかった」。ブルースクリーンと自動保存なしの時代を根拠に、今のほうがずっと良いという反論
**一言で**：1990 年から PC を使ってきた筆者が、「昔のソフトは良かった」という懐古に反論した。

- 3 時間かけた文書がクラッシュで消えるのが日常だった。2010 年に Google Docs チームが Ctrl+S を計測したところ、非編集操作の上位 5 位に入っていたという。手動デフラグが必要で、古い PC は起動に 20 分かかることもあった。
- Diablo II ではクライアント改造やアイテム複製が横行していた。1998 年頃のゲームには、部隊が 255 を超えるとクラッシュするものがあった。

**So what**：AI が書くコードの品質を議論するとき、比べる基準を「昔の理想」ではなく「実際の昔」に置く視点。筆者の経験談で、データによる比較ではない。

## 12. Apple は約 30 億パラメータの LLM を iPhone に収める。重みは 2 ビット、KV キャッシュは 37.5% 削減、2026 年の新モデルは総 20B のスパース構成
![](https://substackcdn.com/image/fetch/$s_!yHZ5!,w_1200,h_675,c_fill,f_jpg,q_auto:good,fl_progressive:steep,g_auto/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fe4e1b752-caa3-4110-b656-7c28871ac8bf_3778x1958.png)
**一言で**：ByteByteGo が、Apple がメモリ・帯域・電力の制約の中で端末上の LLM を動かす技術をまとめた。

- 3B を 16 ビットで持つと約 6GB。旧モデルは 2 ビットと 4 ビットの混在で平均 3.7 ビット、約 1.39GB。新モデルはデコーダーの重みを 2 ビット、埋め込みを 4 ビットにし、量子化を想定した学習で精度低下を抑える。
- モデルを 5:3 の深さで 2 ブロックに分け、後半が前半最終層の Key/Value を再利用して KV キャッシュを 37.5% 削減。タスクごとの LoRA アダプター（ランク 16、数十 MB）で基盤モデルを共有する。
- 2026 年の新モデルは AFM 3 Core と、総パラメータ 20B で性能に応じて 1〜4B だけを動かす AFM 3 Core Advanced。処理が重いときは Private Cloud Compute に送り、Google Cloud の NVIDIA GPU 上でも動くようになった。

**So what**：「クラウドの大型モデル」と「端末の小型モデル」を使い分ける設計が、具体的な数字で見える。元資料の Apple のブログは未確認で、ByteByteGo の整理に基づく。
