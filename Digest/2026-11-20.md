- 公開 PoC が自社のスタックに効くかの確認も拒否された。悪意ある攻撃者は安全対策のないモデルを使えるので、正当な防御側だけが制限されるのは不公平だと主張している。
- 結局 GLM 5.3 と記載のモデルで問題を実証し、修正と検証まで行った。Anthropic が規制当局の反応や参入障壁を狙っているのではないか、という著者の推測も添えている。

**So what**：個人の体験談で、安全対策の発動条件は記事からは分からない。ただ、エージェントの封じ込めが「守る側の作業」を止める副作用の例として読める。

## 14. PostgreSQL 19 リリース。VACUUM FULL を置き換える REPACK CONCURRENTLY、実行計画の固定、JIT は既定で無効に
![](https://www.postgresql.org/media/img/about/press/elephant.png)
**一言で**：PostgreSQL 19 が 11/19 にリリースされ、運用管理と分散の機能が多く入った。

- `REPACK (CONCURRENTLY)` が読み書きをブロックせずにテーブルの肥大化を解消する。`pg_stash_advice` は queryid に基づいてアプリを変えずに遅い計画を直せる。外部キーチェックの改善で、一括 INSERT がほぼ 2 倍速くなったという（外部テスト）。
- 開発者向けに `INSERT ... ON CONFLICT DO SELECT`、`WAIT FOR LSN`（スタンバイでの read-your-writes）、ウィンドウ関数の `IGNORE NULLS` などが入った。
- JIT は既定で無効になった。md5 認証は成功時に警告が出るようになり、RADIUS 認証のサポートは削除された。

**So what**：メジャーリリースなので、md5 認証や RADIUS を使っている環境は、アップグレード前に確認が要る。

## 15. OpenJDK の AVX-512 Base64 デコーダにヒープ破壊のバグ。9 月に報告されたが PR は未マージのまま閉じた
![](https://opengraph.githubassets.com/b0b0c2ccb75297126e183ada14059c37d5742916cd03dbd0529a28dd9dec6a2a/openjdk/jdk/pull/32781)
**一言で**：OpenJDK HotSpot の x86_64 AVX-512（VBMI）版 Base64 デコーダが、不正な短い入力で出力バッファを超えて書き込む不具合が、GitHub の PR で話題になった。

- 出力サイズの計算が負になって `output_mask` が不正になり、ヒープが壊れる。正しい入力（長さが 4 の倍数）では起きず、不正な入力でのみ起きる。
- PR #32781 は 9/9 に作成され、11/4 に「他者に引き継がれた」としてクローズ、11/20 にブランチが削除された。PR には正式な CVE 番号や修正コミットの記載はない。
- RCE にできるかは、ページ内では確認されていない（コメント投稿者が問うにとどまる）。

**So what**：影響は AVX-512 VBMI を使う環境に限られる。記事は PR の記録なので、公式の評価（CVE や修正版）が出るのを待って判断するのがよい。
