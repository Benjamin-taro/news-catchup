## 1. GitHub が Copilot の実行基盤 43 万行を、AI エージェント群と開発者 1 人で数か月かけて Rust に移植
![](https://substackcdn.com/image/fetch/$s_!t5iH!,w_1200,h_675,c_fill,f_jpg,q_auto:good,fl_progressive:steep,g_auto/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F2e64b9e1-d8ca-427a-b096-38cffbb4851e_4024x1604.png)
**一言で**：GitHub は Copilot の共通ランタイムを TypeScript から Rust へ書き直し、AI エージェントを使った開発者 1 人が数か月で終えたという（通常は大人数で約 2 年の規模）。

- 移植対象は本番の TypeScript 約 43 万行（当初見積もりは約 13 万行）。コンポーネントごとに 1 本の PR で置き換え、旧コードは同じ変更で削除した。AI のトークン費用は約 12 万ドル（約 1,360 億トークン）。
- 調整役のエージェントが約 3 万行のファイルを 1 時間かけて分析し、15 の子セッションに分割。複数モデルのレビューエージェントが旧新コードを 1 行ずつ突き合わせ、人間は設計・インターフェース契約・リスクの高い箇所に集中した。
- 結果はクライアント作成から 1 ターン完了までが 5.25 秒から 292 ミリ秒（約 18 倍）、10 クライアント時のメモリ増は 1,383MB から 126MB。一方で、整数が小数になる微妙な退行や、エージェントがテストを弱める懸念が出ており、強い E2E テストが前提だったと書かれている。

**So what**：「書く」作業はエージェントに寄せ、人は設計・契約・検証の仕組みづくりに回るという Q1 の見立てに沿う実例。ただし費用や検証の設計は記事の自己申告で、第三者による品質比較はない。

## 2. Claude Code の「今後は確認しない」承認が、パスワードを公開 GitHub リポジトリへ漏らしている
![](https://lh3.googleusercontent.com/J6_coFbogxhRI9iM864NL_liGXvsQp2AupsKei7z0cNNfDvGUmWUy20nuUhkREQyrpY4bEeIBuc=s0-w300-rw)
**一言で**：セキュリティ企業 Apiiro は、Claude Code が承認済みコマンドを平文で保存する設定ファイルから、公開リポジトリに秘密情報が漏れていると報告した。

- `.claude/settings.local.json` の公開コピー 10 万 4,185 件のうち 1,122 件（約 1.1%）に実際の秘密情報があった。履歴や保存された会話記録まで含めると 1,994 リポジトリで 2,539 件、DB パスワード 379 件、Supabase のサービスロールキー 122 件、AWS キー 23 件など。
- 「Yes, and don't ask again」を選ぶと、コマンドに含まれるパスワードごと許可ルールとして保存される。ファイルは開発者の全体 gitignore には入るが、プロジェクトの `.gitignore` には入らない。比較した 16 のエージェントのうち、既定でこの形で保存するのは Claude Code だけだと Apiiro は述べる。
- Gitleaks が 564 件、TruffleHog が 643 件を検出し、215 件は両方とも見逃した。`PGPASSWORD=` のようにコマンド中に直接書かれたパスワードは鍵の形式に当たらないため。対策は漏れた認証情報の失効、ファイルの追跡解除、環境変数の利用、`.claude/` のスキャン対象への追加。

**So what**：エージェントに権限を渡す運用では、「承認の記録」自体が漏えい経路になる。Q7 の「業務側でどこまで自由を許すか」を考える具体材料。数字は Apiiro の報告で、二次報道（LDS）経由で確認した。
