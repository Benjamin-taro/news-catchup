## 1. Claude で作ったアプリを Mac / Windows のデスクトップアプリとして入れられるように。権限は 3 段階、全プランでベータ
![](https://www.itmedia.co.jp/news/article/ogp/2611/25/2000003431/10012879/2048)
**一言で**：Anthropic が 11/24、Claude のアーティファクトを「Install as app」でデスクトップアプリ化する機能をベータで公開した。

- パッケージ化や署名は不要で、Claude アカウントをそのまま使うため API キーも要らない。元のアーティファクトを直すとアプリも自動更新され、リンクで共有すれば受け取った人もインストールできる。
- 権限は「標準（ブラウザ相当）」「強化（最前面表示・グローバルショートカット・通知）」「フルアクセス（確認なしでプログラムを実行し、ファイルの読み取り・変更・削除ができる）」の 3 段階。フルアクセスは自分が作ったアプリ（Team / Enterprise では同じ組織のメンバーが作ったもの）にだけ付けられ、更新のたびに再確認される。
- Team は機能が最初から有効でフルアクセスは無効、Enterprise はオーナーが有効にするまで使えず、管理者が組織全体で権限を設定できる。HIPAA 対応の組織では使えない。Anthropic はインストール前の審査をしないと明記している。

**So what**：社内の小さな業務アプリを非エンジニアが作って配る道が公式に開いた一方、業務側ではフルアクセスの既定オフ・管理者の制御が付いており、Q7 の「業務側にどこまで自由度を渡すか」の線引きの実例になる。X では「社内業務アプリは自分で作る時代」という反応が出ているが、権限の運用実績はまだない。

## 8. Spring AI 2.1 は、承認が要るツール呼び出しで処理を止め、再起動後も再開できる。承認待ちの状態をセッションログに残す
![](https://spring.io/img/og-spring.png)
**一言で**：Spring の公式ブログが、Human in the Loop（人の承認）を扱う仕組みを解説した（11/24）。

- ツールに `requiresConfirmation = true` を付けるか、プロパティでツール名を指定するか、引数に応じたポリシー Bean で承認対象を決める。承認待ちがあるとループはそのツールを実行せず応答を返し、アプリが呼び出しごとに許可・拒否（理由はモデルに返る）を返す。
- 状態は Spring AI Session Extensions のログに「承認待ち」として記録され、別プロセスが再起動後にセッション ID から再開できる。
- 制限：Session Extensions 0.11.0 は最初のリリースで API が変わりうる。止まった処理を管理するリースがなく、プロセスが落ちたターンは手動で中断する。承認の判断はツール呼び出しのキーで行うため、一部のモデルでは古い判断が新しい質問に誤って適用されうる。

**So what**：業務側でエージェントに任せる際の「誰が承認し、止まっている間どうするか」を、Java の業務アプリの標準部品にする動き。Q7 の業務側の運用に直接関わるが、まだ初期版。
