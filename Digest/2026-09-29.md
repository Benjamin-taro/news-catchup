## 1. 「AI を使い始めて品質が落ちた外注先が、それに気づいていない」という話
![](https://assets.st-note.com/production/uploads/images/315969728/rectangle_large_type_2_bdc2e230ad54ec19fe2965dea586c63b.png?fit=bounds&quality=85&width=1280)
**一言で**：paiza 創業者が紹介した「AI で品質が落ちたのに本人は気づいていない外注さん」の話が大きな反響を呼び、業界をまたいだ現象として議論になっている。

- 元の投稿は X で 45 万回表示、4,500 いいね以上。ライティング、デザイン、プログラミングなど、さまざまな業界から「うちでも起きている」という声が集まった。

**So what**：昨日の「手書きコーディングは終わった」論争の、発注側から見た実例。AI 時代に残る価値は「出力を正しく疑えること」だという点で、議論がそろってきている。

## 2. Claude Code が 103 秒で 4.8 万ファイルを削除、「本気の AI 製品」に必要なもの
![](https://cdn.mos.cms.futurecdn.net/MZeWJhJjT34M4nQvMMX7fg-1376-80.jpg)
**一言で**：コーディングエージェントの事故が報告され、「AI 製品は検証と安全装置を本来の機能として持つべきだ」という主張が出ている。

- **事故**：Claude Code が作った掃除用スクリプトが、Windows の「ジャンクション」（別の場所を指すフォルダ）を普通のフォルダと誤認した。リンク先の実際の作業ファイル 48,218 個を 103 秒で削除し、Git の履歴まで壊して復元できなくなった（Reddit での報告）。
- **Glyph の主張①**：今の AI 製品は「AI は間違えることがあります」と小さく書くだけで、検証の責任をユーザーに押し付けている。主張ごとにチェック欄を付けるなど、検証を第一級の機能にするべきだという。
- **Glyph の主張②**：コーディングエージェントには、ファイル操作の厳しい制限、リポジトリの自動スナップショット、「自動モード」の廃止を求めている。

**So what**：エージェントに実際のファイルやシステムの権限を渡したときの失敗が、具体的な数字で出てきた。企業に導入する際は「何をさせないか」の設計が中心になる。これは 9/28 に取り上げた、各社が実行基盤を相次いで発表した流れの裏側にあたる。

- 時系列：9/25 9:07 に検知し、同日に第 1 報。9/26 7:25 までに侵入経路と攻撃元との通信を遮断し、9/28 の第 2 報で被害を確定させた。

## 8. 15 年使った Git から Jujutsu に乗り換えた理由
![](https://res.cloudinary.com/zenn/image/upload/s--LShNO1fJ--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:Jujutsu%2520%25E3%2581%25A8%25E5%2587%25BA%25E4%25BC%259A%25E3%2581%2584%25E3%2580%258115%2520%25E5%25B9%25B4%25E4%25BD%25BF%25E3%2581%25A3%25E3%2581%259F%2520Git%2520%25E3%2581%25AB%25E3%2582%2582%25E3%2581%2586%25E6%2588%25BB%25E3%2582%258C%25E3%2581%25AA%25E3%2581%258F%25E3%2581%25AA%25E3%2581%25A3%25E3%2581%259F%25E7%2590%2586%25E7%2594%25B1%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:oukayuka%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyL2E1MDUwMjcxNTAuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：Git と互換性のあるバージョン管理ツール「Jujutsu」に移った開発者が、もう Git には戻れないと語る記事。

- 作業ディレクトリの状態がそのままコミットになり、add → commit の手順がいらない。バージョン管理にかかる頭の負担が減ると著者は言う。
- 変更を消しても操作ログから戻せるので、実験を気軽にできる。
- 履歴を直すときは、目的の地点に移ってファイルを書き換えるだけで、必要な rebase は自動で行われる。AI が作ったコードを何度も直す今の開発に向いているという。

**So what**：AI と一緒に開発するのが当たり前になり、「開発者の道具そのもの」が見直され始めている兆し。

## 9. 暇な NPU で DOOM を動かせるか、Claude が「掛け算の暴力」で実現
![](https://pc.watch.impress.co.jp/img/pcw/list/2142/551/1.png)
**一言で**：Intel CPU に内蔵された NPU（AI 処理用のチップ）で、Claude Code がゲームの DOOM を約 9fps で動かした。

- 「DOOM も移植できるよね」と頼むと、Claude Code は NPU の制約に合わせて「自前で実装する」と決め、アルゴリズムを書き換えていった。
- NPU は条件分岐が苦手なので、「弾が当たったら体力 −10」を「体力 = 体力 − 10 × 当たり判定」のように掛け算に置き換えた。分岐の両方を計算し、不要なほうに 0 を掛けて捨てる。
- 途中で何度か利用上限に達したが、最終的に完成した。

**So what**：遊びの記事だが、AI エージェントに制約の厳しいハードウェアで試行錯誤させると何ができるかがよく分かる。
