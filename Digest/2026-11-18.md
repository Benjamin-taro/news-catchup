## 2. curl の作者 Stenberg「書くことは難しくない」──エージェントが C 18.5 万行を Rust 34 万行に書き換えても、価値はテストと API 安定性にある
![](https://daniel.haxx.se/blog/wp-content/uploads/2023/09/old-machine.jpg)
**一言で**：curl の Daniel Stenberg 氏が、AI エージェントによる curl の Rust 書き換えが現れたことを受け、書き換えを信じず継続的な改善を選ぶ理由を書いた。

- 書き換えはエージェントが約 18.5 万行の C を約 34 万行の Rust にしたもの（行数は Stenberg 氏が数えた）。報告されたコストは 8,600 ドルだが、コメント欄は API 換算の推計で実際の請求額ではないと指摘している。
- curl 本体は 3 週間強で 300 超のコミット（うち約 200 がバグ修正）を取り込んだ。2026 年に確認された脆弱性 81 件のうち、メモリ安全な言語なら防げたと思われるのは 14 件（17.3%）。Rust 版でも 67 件は残る計算になる。
- 彼は、curl の価値は数十年の API/ABI の安定、テストスイート、メンテナと共同体にあり、コードを書くこと自体は難しくないと述べる。

**So what**：「残るのは構造・検証・長期の維持判断」という Q1 の見立てを、第三者の数字（脆弱性の内訳）つきで支持する材料。主張は 1 人の著名メンテナの意見。

## 4. Java4Shell（CVE-2026-114938）：OpenJDK の Base64 処理に深刻な欠陥、Jira・Jenkins・Kafka などで RCE を実証
![](https://calif.io/java4shell/poster.jpg)
**一言で**：Calif が、OpenJDK 17.0.6 以降の x86-64（AVX-512 VBMI）向け Base64 処理のバッファ超過書き込みを公表し、Oracle らがパッチを出した。

- CVSS 4.0 で 9.2。50 バイトの領域に 64 バイトを書き込む。末尾に `=` のある不正な入力で、認証なしの攻撃者がヒープを読み出し、RCE にも至りうる。Keycloak・Jira・Confluence・Jenkins・Kafka・Elasticsearch の既定設定で RCE を実証した。
- 対象は Corretto・Temurin・Oracle Java SE など OpenJDK 由来の配布版。Intel Ice Lake 以降や AMD Zen 4 以降が該当し、ARM64 は対象外。パッチは 11/17 に公開。未適用なら `-XX:-UseBASE64Intrinsics` で回避できる。
- 発見に約 1 時間、動くエクスプロイトにさらに約 2 時間、AI のトークン費用は 200 ドル未満だったと報告している。

**So what**：Java は大企業の基盤なので影響範囲が広く、まず自社の JDK とハードウェアの該当確認が要る。「AI で安く短時間に見つかった」という数字は報告者の自己申告。

## 7. Microsoft が警告：コーディングエージェントの「デバイスコード認証」を悪用すると、1 回の承認で会話履歴や私有リポジトリまで届く
![](https://www.microsoft.com/en-us/security/blog/wp-content/uploads/2026/03/MS_Actional-Insights_Phishing-social-engineering.jpg)
**一言で**：Microsoft のセキュリティ研究チームが、GitHub Copilot CLI を例に、攻撃者が始めたデバイスコード認証をユーザーが承認すると何が起きうるかを検証した。

- 承認ページは本物の GitHub なのでドメインでは見分けられない。承認後に起こりうるのは、リモート操作によるエージェントへのコマンド実行、`/memory` への偽の記憶の書き込み、クラウド同期された過去セッションの閲覧、`repo` などのスコープによる私有リポジトリへのアクセスの 4 つ。

## 11. 推論させすぎると LLM はなぜ間違えるのか──「2+3」に 13 通りの解を出す無駄と、誤った前提

**So what**：推論モデルを「長く考えさせるほど良い」で使わない設計判断の材料。入門寄りの解説で、数字の一部は記事の外のもの。
