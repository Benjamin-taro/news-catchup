## 6. 「AI なしで TODO アプリを手書き」234 分。止まった原因は文法でなく「自分が何をしたいか決まっていなかった」こと
![](https://res.cloudinary.com/zenn/image/upload/s--98RnbBvd--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:%25E4%25B9%2585%25E3%2581%2597%25E3%2581%25B6%25E3%2582%258A%25E3%2581%25AB%25E6%2589%258B%25E3%2581%25A7%25E3%2582%25B3%25E3%2583%25BC%25E3%2583%2589%25E6%259B%25B8%25E3%2581%2584%25E3%2581%25A6%25E3%2581%25BF%25E3%2581%259F%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_34:km%2Cx_220%2Cy_108/bo_3px_solid_rgb:d6e3ed%2Cg_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyLzY2NmFjODVmNmMuanBlZw==%2Cr_20%2Cw_90%2Cx_92%2Cy_102/co_rgb:6e7b85%2Cg_south_west%2Cl_text:notosansjp-medium.otf_30:TRIPLE%2520THREE%2520Tech%2520Blog%2Cx_220%2Cy_160/bo_4px_solid_white%2Cg_south_west%2Ch_50%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyLzNmMTZhOTA0NWYuanBlZw==%2Cr_max%2Cw_50%2Cx_139%2Cy_84/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：Zenn の記事で、著者が 120 分の制限で React + TypeScript の TODO アプリを手で書き、同じお題を AI に頼んだ場合と比べた。

- 予定 4 機能のうち実際にできたのは追加と完了の 2 つで、約 234 分かかった。詰まりは配列 state への追加（18 分）、完了状態を更新していなかった（12 分）、useId の key 重複（11 分）など。書き方を知らなかった時間は合計 28 分。
- AI は一文の指示で 1 分 20 秒、4 機能・193 行を返した。頼んでいない残り件数表示、空入力の禁止、localStorage への保存も入っており、著者はこれらを自分では考えていなかったと振り返る。
- 結論は、手書きでも AI との開発でも止まる原因は「何をしたいのか分かっていない」ことで、止まったらやりたいことを 1 行で書く、というもの。

**So what**：コードを書く速度より「何を作るかを決める」側に残る仕事がある、という Q1 の見立てに沿う個人の体験談。1 人・1 題材の記録。

## 7. AGENTS.md を置くだけで AI コーディングエージェントを乗っ取れる。Downloads フォルダから起動した Codex で成功率 90%
![](https://www.bleepstatic.com/content/hl-images/2026/10/23/robot.jpg)

- 顧客の PC で見つかった事例で、AGENTS.md が指示した npm パッケージ「function-color」を入れようとした。Web ページから自動でファイルを置かせる経路もありうる。
- 無害なペイロード（電卓を開く）での成功率は Codex で 90%、Claude Code で約 50%。Claude Code では OAuth トークンを盗む関連手法も示された。同社の統計では、数百の顧客が ~/Downloads からエージェントを起動し、Claude Code だけで 1,300 回超のセッションがあった。
- 対策は、作業ディレクトリをプロジェクトのルートに限る、未知の AGENTS.md / CLAUDE.md を確認する、承認プロンプトとサンドボックスを有効にする、など。

**So what**：指示ファイルの置き場所が攻撃面になるという例。成功率は研究者の自社テストの数字。

**一言で**：Zenn の記事で、Claude Code が聞きすぎる・任せすぎる問題を、任せる範囲を事前に 3 区分で決めて解消した運用を紹介した。

- 区分 1「確認なしでよい」はコード編集・commit・本番反映・本番 DB の読み書きなど（承認日を併記）。区分 2「必ず確認」は課金・送金・新規契約に絞る。区分 3「確認の有無によらず守る」は大量削除前の件数確認とバックアップ、API の月間予算、設定上書き前の差分比較。

- 本番の資格情報など重い操作は自動許可されないことがあり、AI が「できない」と言ったら境界が働いたと捉えて自分で実行する。

**So what**：個人運用では本番 DB まで任せる自由度がある、という Q7 の見立てを支持する例。業務の現場でこの線引きが許されるかは別の話で、1 人の運用記録。
