## 1. PostgreSQL 19 がリリース延期、背景に「LLM によるコードレビュー」で大量に見つかった欠陥
![](https://www.publickey1.jp/2026/postgresql19-logo.png)
**一言で**：PostgreSQL 19 は多数の新機能を取り下げて正式版が例年より遅れ、コミッターは原因の一つに LLM を使ったコードレビューで欠陥が大量に見つかったことを挙げている。

- 例年は 9〜10 月に出る正式版が、今回は RC2 が 11/12 に公開され、正式リリースは 11/19 の予定。9 月下旬の β4 で SQL/PGQ、チェックサムのオンライン切り替え、FOR PORTION OF など多数の機能が取り下げ・削除された。
- コミッターの Peter Eisentraut 氏は 10/9 のブログで、LLM を使ったレビューにより、以前なら数年かけて表に出ていた細かな問題が早期に大量に見つかるようになったと説明。約 40 件の不具合報告を抱え、β 期間内に直せないアーキテクチャ上の欠陥もあったという。
- Robert Haas 氏も 10/30 のブログで、LLM でバグを見つけたという報告が非常に多く、コミッターがその修正に追われていると書いている。

**So what**：AI のレビューが「見つける側」を自動化した結果、直して判断する人間側が詰まるという構図が、PostgreSQL ほどの基盤で第三者の数字つきで出た。レビューが自動化された実例であると同時に、人の判断が残る場所（どの機能を戻すかの決定）も見える。ただし因果は 2 人のコミッターの見方で、公式の理由は「信頼性とスケジュールの予測可能性」とされている。

## 2. 古い Bitly 短縮リンクが乗っ取られ、Burger King や McDonald's の 2011 年のツイートが別ページへ
![](https://ransomnews.com/wp-content/uploads/2026/11/burger-king-tweet-bitly-link-hijack-2026-cover-1024x576.png)
**一言で**：Bitly の古い・未使用の短縮リンクが再登録され、企業や政治家の過去の投稿のリンク先が無関係なページに書き換わる事態が 11/15 に起き、Bitly は悪用を認めて対応を始めた。

- Burger King の 2011 年のツイートのリンクは 11/15 05:32 UTC に再作成され、Wikipedia の収容所の一覧へ飛ぶようになった（引用投稿は約 220 万回表示）。McDonald's も 18 分前に同様に再作成された。アカウントが侵害されたわけではない。
- Trump 氏の 2009〜2013 年のツイートの Bitly 97 本を調べたところ、40 本は元のまま、49 本は再作成済み（うち 48 本は 2023-05-26 の 17 分間に作成）、7 本は無関係なページ、2 本は暗号資産サービスを装うドメインに向いていた。
- Bitly は 19:13 UTC に「古い未使用リンクを悪用された」と X で認め、関与アカウントの停止とリンクの無効化を発表。削除済みリンクの後半は再利用できないとしていた同社のヘルプ記述と作成日の分析は食い違う。

**So what**：検証済みアカウントの古い投稿やメール・文書・QR コードに埋まった短縮リンクが、詐欺の入口になりうる。外部サービスに依存したリンクは「いつか他人のものになる」前提で棚卸しする必要がある。なお、これは Ransomnews の分析で、Bitly は被害数を公表していない。

## 4. Claude Code のコミットを 100 行以内に分けさせる：CLAUDE.md より pre-commit フックが効いた
![](https://res.cloudinary.com/zenn/image/upload/s--NY1WRzZV--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:Claude%2520Code%2520%25E3%2581%25AE%25E3%2582%25B3%25E3%2583%259F%25E3%2583%2583%25E3%2583%2588%25E3%2582%2592100%25E8%25A1%258C%25E4%25BB%25A5%25E5%2586%2585%25E3%2581%25AB%25E5%2588%2586%25E3%2581%2591%25E3%2581%2595%25E3%2581%259B%25E3%2582%258B%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:%25E3%2582%25A2%25E3%2582%25BB%25E3%2583%25AD%25E3%2583%25A9%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyL2FmOTgyYjM3NzMuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：acerola_jp 氏が、大きな変更を頼んだときのコミットサイズを、CLAUDE.md の指示と git の pre-commit フックで比べた。

- 指定なしでは 1 コミットに 298 行・426 行が集まった。CLAUDE.md に「100 行以内」と書くと 2 回とも 6 コミットに分かれ、最大は 59 行・66 行。
- pre-commit フック（追加と削除の合計が 100 行超で拒否）では、最初の一括コミットが拒否され、Claude 自身が 6 つに分け直した（最大 76・80 行）。
- 「まとめて 1 つに」と頼むと、CLAUDE.md の回は 1 回目に 139 行で上限を超えた。フックの回は 2 回ともコミットせず人の判断を求め、`--no-verify` での回避はしなかった。各条件 2 回ずつで、PR 全体の行数は 304〜427 行のまま減らない。

**So what**：指示は普段の動きを決めるが、依頼と衝突すると負けうる。確実に守らせたい線引きはフックのような外側の仕組みに置く、という使い分けが数字で見える。レビューしやすい単位に AI の出力を切る工夫にもなる。ただし試行回数は少ない。

**一言で**：acerola_jp 氏が Claude Code（Sonnet 5.5）で 4 つの独立課題を直列と並列で比べ、並列は仕事が重いときだけ速くなることを示した。

- 軽い課題（各 10 回）は直列 33.2 秒・$0.107 に対し並列 42.8 秒・$0.254（時間 1.29 倍、費用 2.37 倍）。重い課題（各 6 回）は直列 61.1 秒・$0.188、並列 45.1 秒・$0.289（時間 0.74 倍、費用 1.54 倍）。
- 並列の所要時間は課題の重さによらず 43〜45 秒前後で、起動と結果の受け取りに固定の時間があると考えられる。32 回すべてで隠しテストに合格し、出来の差は見えなかった。
- 課題は小さな Python に限られ、調査や大きなリファクタリングでは結果が変わりうる。

**So what**：「複数運用で速度を出す」は、仕事の粒度と費用の釣り合いで決まる。並列の恩恵は 1 分を超える重い仕事に限られ、常に得とは限らない。

## 10. 「AI の低品質 PR が増えた」ことを理由に GitHub から Codeberg へ移った Inko 作者

## 14. uBlock Origin に、Web サイトから任意の信頼フィルターを足せる UXSS（修正済み）
![](https://iter.ca//ubo-epicker.png)
**一言で**：要素ピッカー経由で悪意ある Web サイトが任意の信頼されたフィルターを追加し、あらゆるサイトで JavaScript を実行できる 1 クリックの脆弱性が見つかり、修正された。

- 主に影響したのは Firefox の MV2 版 uBlock Origin。MV3 版の uBO Lite にも軽い同種の問題があった。
- 攻撃者は、拡張ごとのランダムな UUID を既定のフィルター規則の挙動から取得し、ピッカーを iframe に埋めてメッセージを送る。`opt` フィールドの改行で信頼されたスクリプトレットのフィルターを追加できた。
- 修正は、本物のピッカーだけが知る秘密のトークンを初回メッセージに付ける方式。GitHub のアドバイザリ GHSA-cmqw-9r2w-6wv2 がある。

**So what**：広告ブロッカーのような強い権限を持つ拡張は、1 クリックの経路が全サイトへの権限につながる。ブラウザ拡張の権限設計は、エージェントに権限を渡す設計と同じ論点を持つ。
