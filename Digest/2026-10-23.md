## 11. UUIDv7 は「単調増加・作成時刻・推測困難」を保証しない。時計を 1 時間戻した実験で、タイムスタンプのずれが際限なく広がった
**一言で**：UUIDv7 に期待されがちな性質は RFC では保証されておらず、実装ごとに違うと検証した記事。

- RFC 9562 は実装がタイムスタンプを変えてよいと定め、ずれの上限もない。Python の `uuid.uuid7()` では、時計を 1 時間戻して高負荷をかけると、差が 3695・3795・3894・3994 秒と縮まず増え続けた。
- 単一ノードでもカウンタのない実装では順序が逆転しうる。複数ノード間の単調増加は、Lamport clock の研究から原理的に不可能。再起動をまたいで最後の値を永続化する実装は、著者の調べた範囲で見つからなかった。
- ID に時刻が埋め込まれるため、アカウント作成日などが漏れる。ただし著者は優先度の低い問題とし、「おおむね順序づいた ID」としては有用と述べる。

**So what**：「新しい標準だから安心」ではなく、採用時にどの性質を実装が保証するか確認する、という実務の注意点。

## 12. 「Docker is weird」。コンテナは 5 つほどの Linux カーネル機能のコート、イメージはただのフォルダ
**一言で**：趣味でコンテナランタイムを自作した著者が、Docker の仕組みの奇妙な点を紹介した。

- コンテナはホストのカーネル上の制限付きプロセスで、namespaces・cgroups などの組み合わせ。イメージは展開したフォルダを `chroot` / `pivot_root` でルートにして `bash` を動かすだけ。
- Go は多くの syscall がシングルスレッドで要るのに合わない。`runc` は Go の初期化前に動く C のモジュールを持ち、`/proc/self/exe` を再実行して疑似 fork をしている。
- Docker デーモンは通常 root で動く。rootless ではネットワークスタックをユーザー空間で再実装する必要がある。

**So what**：Kubernetes / OpenShift を使う立場で、土台の仕組みを自作で理解する入口になる。
