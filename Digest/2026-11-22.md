## 1. リーマン予想の Lean 証明、Lean・Mathlib コミュニティが「公式に検証済み」と声明（11/21 の続報）
![](https://leanprover-community.github.io/blog/meta-twitter.png)
**一言で**：Alpöge 氏が 11/20 に公開したリーマン予想の Lean 証明について、Lean と Mathlib のコミュニティが 4 つの基準で検証したとする共同声明を出した。

- 証明は Mathlib だけに依存する Lean ライブラリで、規模は約 1,700 万行。数十人が同じ証明のエクスポートを再現し、Lean のカーネルや第三者製を含む複数のチェッカーを通った。
- 定理の述べ方が Mathlib の `RiemannHypothesis` の定義と一致することも、2 つの専用ツール（`comparator`、`con-leche --compare`）で確認した。検証は元のソースではなく、悪意あるコードを避けるための無害化したエクスポートに対して行っている。
- 声明が保証するのは形式コードの正しさで、数学的なアイデアの理解ではない。「新しいアイデアを数学者が説明する作業はこれから」と書き、査読の代わりでもないと断っている。ページは AI の利用には触れていない。

**So what**：形式検証が済むと「証明が正しいか」の確認は機械側に移るが、何が証明の鍵だったかを読み解く仕事は人に残る。11/21 の初報では人の精査待ちだった点が一段進んだ。

## 3. Claude Code のフックが壊れると操作は通る。`"onFailure": "block"` の 1 行で 14 通り中 10 通りが止まる
![](https://res.cloudinary.com/zenn/image/upload/s--mcNUZh9J--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:Claude%2520Code%25E3%2581%25AE%25E3%2583%2595%25E3%2583%2583%25E3%2582%25AF%25E3%2581%258C%25E5%25A3%258A%25E3%2582%258C%25E3%2581%259F%25E3%2582%2589%25E6%2593%258D%25E4%25BD%259C%25E3%2581%25AF%25E6%25AD%25A2%25E3%2581%25BE%25E3%2582%258B%25EF%25BC%259F%252014%25E9%2580%259A%25E3%2582%258A%25E4%25B8%25AD11%25E9%2580%259A%25E3%2582%258A%25E3%2581%25A7%25E9%2580%259A%25E3%2582%258A%25E3%2580%2581%2522block%2522%2520%25E3%2581%25AE1%25E8%25A1%258C%25E3%2581%25A7%25E3%2581%259D%25E3%2581%25AE%25E3%2581%2586%25E3%2581%25A1...%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:%25E3%2581%258A%25E3%2581%2598%25E3%2581%2595%25E3%2582%2593AI%25E3%2583%25A9%25E3%2583%259C%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyLzZhYjlkMjRhMmYuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：ojisan_ai_lab さんが PreToolUse フックをわざと壊し、操作が止まるかを Claude Code 2.1.327〜2.1.330 で実測した。

- command フックを 14 通りの壊し方で試すと、`onFailure` なしでは 11 通りで操作が通った。`"onFailure": "block"` を足すと、そのうち 10 通りが止まった。壊れた JSON を出して exit 0 で終わる形は、block を書いても通った。
- mcp_tool フックは版で分かれ、2.1.327 では通り、2.1.328 以降で止まった。公式ドキュメントにも v2.1.328 以降が必要とある。著者自身のフックにも `onFailure` が書かれていなかった。
- 測定は Windows 11 の `claude -p` で、組み合わせごとに 1 回ずつ。macOS・Linux や http フックは未測定。block を足すと、フックが壊れている間は該当操作が全部止まる。

**So what**：「止めるためのフック」は、壊れたときに黙って通る既定のままだと安全装置にならない。自分の settings の PreToolUse に `onFailure` があるかを見る価値がある。

## 10. 自動化の出力を信じる前の 3 つの検証ゲート：実行ログ・件数照合・差分確認
![](https://res.cloudinary.com/zenn/image/upload/s--LnWzT5UO--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:%25E8%2587%25AA%25E5%258B%2595%25E5%258C%2596%25E3%2581%25AE%25E5%2587%25BA%25E5%258A%259B%25E3%2582%2592%25E4%25BF%25A1%25E3%2581%2598%25E3%2582%258B%25E5%2589%258D%25E3%2581%25AB%25E9%2580%259A%25E3%2581%25993%25E3%2581%25A4%25E3%2581%25AE%25E6%25A4%259C%25E8%25A8%25BC%25E3%2582%25B2%25E3%2583%25BC%25E3%2583%2588%2520%25E2%2580%2594%2520%25E5%25AE%259F%25E8%25A1%258C%25E3%2583%25AD%25E3%2582%25B0%25E3%2583%25BB%25E4%25BB%25B6%25E6%2595%25B0%25E7%2585%25A7%25E5%2590%2588%25E3%2583%25BB%25E5%25B7%25AE%25E5%2588%2586%25E7%25A2%25BA%25E8%25AA%258D%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:automation_lab%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly96ZW5uLWRldi5naXRodWIuaW8vZGVmYXVsdC1hdmF0YXJzL2RhcmsvYS5wbmc=%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：Zenn の記事が、自動化の「終了コード 0」だけで信用せず、3 段で中身を確かめる方法を整理した。

- ログは「スキップの理由と ID」をセットで JSONL に残し、WARN の件数を見るだけで異常の兆候をつかめるようにする。
- 件数は「入力 = 成功 + スキップ + エラー」が成り立つことを、DB・API 呼び出し・出力ファイルなど複数の地点で確かめる。

**So what**：AI が回す自動化でも、人が見る場所を「ログ・件数・差分」に絞る考え方として使える。具体的な計測結果ではなく、著者の整理した手順。

## 13. モニター経由の有線 LAN で下りが 600Mbps に。原因は Realtek チップの USB バースト 4 パケット
![](https://blog.tymscar.com/studio-display-ethernet/og-card.png)
**一言で**：2.5Gbps 回線が Studio Display 内蔵の Ethernet アダプタ経由だと下り約 600Mbps に落ちる原因を、著者がパケット単位で突き止めた。

- アダプタ（RTL8156B）は 1 バーストで 4 パケットしか送れず、Mac からの許可待ちでバッファが溢れ、フレームを落とす。2.03Gbps で 2.7%、2.28Gbps で 13.5% を落とし、ルーターが送信を絞って下りが落ちる。Mac に直結すると下り 2.2Gbps。
- 公式ドライバで約 1.1Gbps、フロー制御を有効にすると約 2Gbps だが、他の機器に遅延が出る。8 パケットのバーストを持つ RTL8157（5Gbps 品）に替えると、2.4Gbps まで落とさず速度が戻った。

**So what**：「回線は速いのに遅い」原因が機器内部のバッファ設計にあった事例。1 人の環境の検証で、他のモニターには当てはまらない可能性がある。
