## 6. AI コーディングエージェントのセキュリティ、MCP では「呼ばれない」ことがある。Semgrep は Hooks で強制実行を提案
![](https://semgrep.dev/assets/mcp-gives-agents-tools-hooks-give-security-control.png)
**一言で**：Semgrep が、エージェントにセキュリティ検査を組み込む方法として、MCP は任意呼び出し、Hooks は毎回必ず実行できる点で役割が違うと解説した。

- MCP はエージェントがいつ使うかを自分で決めるため、必須の統制の置き場所としては弱い。Hooks は環境側がエージェントの動作の節目で必ず介入できる。
- 同社の「Semgrep Guardian」は MCP サーバー、Hooks、Skills を 1 つにまとめ、生成されたファイルを毎回スキャンして、問題がなくなるまで再生成させる。

**So what**：エージェントの安全性を「お願いするプロンプト」ではなく「決定的に実行される仕組み」で担保する方向が具体化している。ただし Semgrep は自社製品を売る側なので、主張と宣伝を分けて読む必要がある。

## 7. Codex Cloud が OpenAI アカウントの「本名」を Git の作者情報に書き込み、公開リポジトリで露出
**一言で**：ブログ筆者が Codex Cloud でコード修正を頼んだところ、ChatGPT ではハンドルネームを使っていたのに、コミットの作者に本名が入って公開された。

- 原因は、Codex Cloud が環境のセットアップ時に、ChatGPT のプロフィールではなく OpenAI アカウントの登録情報から Git の Author を自動設定していたこと。
- Force Push で作者を直したが、履歴がリポジトリのタイムラインに残るため、最終的にリポジトリを削除して作り直した。
- 対策は、クラウド環境のセットアップ後、指示を出す前に Author を正しく設定しておくこと。

**So what**：エージェントが「ユーザーの代わりに行う操作」に個人情報が自動で乗ることがある、という身近な事例。権限や情報の扱いは派手な暴走だけでなく、こうした既定値の挙動でも問題になる。
