## 1. 第一生命で従業員12万人分の情報漏えいの可能性、ヤマト運輸も後払い決済に不正アクセス
![](https://www.itmedia.co.jp/news/article/ogp/2610/02/2000001971/10008289/2048)
**一言で**：10/2 に第一生命グループの人事システムとヤマト運輸の「クロネコ代金後払い」への不正アクセスが相次いで公表された。

- 第一生命・第一ライフグループは、9/24 の不正アクセスで従業員約12万人分（うち約7万人は退職者）の情報が漏れた可能性があると公表。従業員番号・氏名・住所・電話番号・所属・職位・上長名などが含まれ、顧客情報への被害は現時点で未確認。

## 4. AI が書いたコードのレビューで疲れる原因は「用語のズレ」、用語を自分の言葉に揃える提案
**一言で**：LLM が付ける命名が自分の感覚とずれていると、レビューの認知負荷が上がるため、用語を統一させる工夫を紹介する記事。

- 例：LLM は抽象化を `MutationIntent` と名付けるが、開発者なら `EditRequest` と呼ぶ、といったズレ。見慣れない用語が数十個たまると、そのたびに頭の中で翻訳が必要になり誤読もしやすい。
- 対策は後処理プロンプト。AI に「標準的でない用語」を洗い出させ、意味と理由を書かせ、代替案を出させる。選んだ用語をコードとドキュメント全体で一括置換する。
- 数字や統計は出ておらず、著者個人の運用の紹介にとどまる。

**So what**：AI でコードを書く量が増えるほど、ボトルネックは書く側から読む側（レビュー）へ移る。レビューしやすい形に整える工夫が新しい仕事になっていく。

## 8. Git 3.0 の SHA-256 既定化は「高くつく誤り」、GitButler 共同創業者が反論
![](https://gitbutler-docs-images-public.s3.us-east-1.amazonaws.com/git-3-sha-256.webp)
**一言で**：Git 3.0 で SHA-256 が既定になる計画に対し、移行コストが大きすぎると主張する記事が HN で話題になった。

- 新しい Git 3.0 のリポジトリは、旧バージョンで作ったリポジトリへ push できず、対応していない Git ライブラリが多く壊れると指摘。Slack やメールにある SHA-1 のリンクも無効になる。
- SHA-1 には衝突攻撃が公開されているが、偶発的な衝突は約1.4セプティリオン個のファイルが必要で非現実的。攻撃も、npm パッケージの書き込み権限を狙う方がはるかに簡単だと主張。
- 代替案は、SHA-1 を残したまま SHA-256 の tree ハッシュを別ヘッダーで足す方法。Chromium（35GB、210万ファイル）のチェックサムは5秒で済んだという。

**So what**：Git はほぼ全開発者の基盤で、既定値の変更は CI/CD や各種ツールにも波及する。賛否はまだ分かれていて、この記事は一方の主張である点に注意。

🔗 [GitButler Blog](https://blog.gitbutler.com/git-3-sha-256) ｜ 60点 ｜ Stack: Platform Engineering / CI/CD（🔥）

## 10. Cloudflare が判断特化の小型モデル「Clef」を公開、エージェント内の分類を高速・安価に
![](https://blog.cloudflare.com/_emdash/api/media/file/01M3TJV43SPQCPKJ6GBXFCDKNE.01M3TJV53VYDMVNCZDPH1FBFYN.png)
**一言で**：Cloudflare が、エージェントの分岐判断や分類向けのオープンウェイトモデル「Clef」と、ファインチューニング用の RL 基盤を 10/1 に発表した。

- Clef と低遅延版 Clef-flash の2種類。Apache 2.0 で Hugging Face に公開し、Workers AI でも使える。画像分類用のビジョンエンコーダと64kトークンの文脈長を持つ。
- 中央値の遅延は Clef-flash が 38.8ms、Clef が 209.3ms。比較対象の Jev は 524.1ms。
- Cloudflare 社内の検証では、同等の LLM 方式の分類4.7秒に対し2.2秒だった。

**So what**：エージェントの中身を大型 LLM だけで回さず、判断部分を小型モデルに任せる設計が現実的になってきた。ただし数字は Cloudflare 自身の測定。
