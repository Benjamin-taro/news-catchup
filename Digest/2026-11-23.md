## 1. OpenAI の主任科学者が、AI 開発に業界共通の「上限」を提案。物差しは perplexity
![](https://images.ctfassets.net/kftzwdyauwt9/6rIIhCRSKrhIfe385Onmcz/aca2d190553c62fd5d49efb5d5ce1eb6/perplexity-and-intelligence-social.png?w=1600&h=900&fit=fill)
**一言で**：OpenAI のチーフサイエンティスト Jakub Pachocki 氏が、perplexity を各社共通の指標にし、監視技術が追いつくまで超えない「共通の上限」を決めようと呼びかけた。

- 自社ベースモデルの log-perplexity を初公開した。GPT-3.5 は約 0.99、GPT-4 は約 0.91、直近のモデルは 0.8 未満。約 0.76 のモデルは社内で長年未解決だった数学の問題に次々と答えたという。
- 次に大きな能力の変化が起きると見る区間は約 0.68〜0.7。各社が評価の規範・レッドチームの安全性ケース・透明性の基準を共同で決めることも提案している。
- 筆者自身が、評価データが各社で違い比較しにくい、タスク性能と直結しない、CoT など事前学習外の進歩は映らない、といった限界を挙げている。ITmedia によれば Altman CEO も X で支持した。

**So what**：「どこまで作るか」を数値で業界が縛る案が、当事者である最大手から出た。数値は OpenAI の社内計測で第三者の検証はなく、他社が同意するかも未定なので、提案として読むのが妥当。

## 2. コーディングエージェントは単体テストに強いが、模擬の職場で最後までやり切れた課題は 1 割未満（SWE-CoWork）
![](https://explainx.ai/images/blog-library/engineers-gear-laptop-hardhat.webp)
**一言で**：実リポジトリ 101 件を使い、同僚役 26 人とやり取りしながら進めさせる新ベンチマークで、最上位のモデルでも全課題を完了できたのは 8% 未満だった。

- 結果は Claude Opus 5.5 が 6.93%、GPT-6 Astra が 7.92%。新機能のテストは 60% 台（F2P）、既存動作のテストは 9 割前後（P2P）まで通るのに、全部そろって通る完了率はこの水準にとどまった。
- 新機能のテスト成績は、同僚から要件を聞き出せた割合と強く相関した（相関係数 約 0.94）。Opus 5.5 は同僚が持つ要件を約 64% しか取れず、「完了」とした要件の 31% がテストで失敗した。
- 要件を最初から全部渡す設定でも、GPT-6 Astra の完了率は 7.92% のままだった。

**So what**：コードを書く部分より、人から要件を引き出し責任を持って仕上げる部分が詰まっている、という数字。ただし数字は解説記事（explainx.ai）の転載で、論文本体との照合はできていない。

## 4. GitHub の 22 リポジトリが、CLAUDE.md や hooks で AI エージェントに「マルウェアを実行させる」罠だった（Bitdefender）

## 6. Claude Code を安全に自走させるなら Docker Sandboxes（sbx）で足りる、という実践メモ
![](https://assets.st-note.com/production/uploads/images/339175432/rectangle_large_type_2_490a1a8344ed92ccfd09322236cc3e11.jpeg?fit=bounds&quality=85&width=1280)
**一言で**：note の記事が、Claude Code や Codex を microVM 内で動かす Docker Sandboxes の使い方と、通信制限の効き方を実機で確かめた。

- 筆者は「9 割くらいのケースはこれで足りる」と見る。Claude Code 標準の `/sandbox` はシェルコマンドしか隔離せず、ファイルツールや MCP はホスト側で動くため、無人運用には不十分だとする。
- 通信は既定で拒否。Balanced を選ぶと GitHub の 3 ホストなどだけ許可され、example.com や YouTube は遮断、`sbx policy allow network` で個別に許可できた。Docker Desktop は不要で、ローカル実行は商用でも無料。
- 注意点：共有フォルダー内の `.env` は読める。Claude Code は既定で `--dangerously-skip-permissions` 付きで起動し、MCP のローカル stdio サーバーはホスト側で動く。

**So what**：「確認を絞る代わりに隔離を厚くする」設計を個人で作る手順が具体的に出てきた。1 人の検証なので、組織での運用は別途有料の管理機能や設定確認が要る。

## 9. CLAUDE.md に書き足した行が守られないのは、置き場が悪いから。指示ファイルと Skill の書き分けを検証
