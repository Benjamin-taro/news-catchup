**一言で**：Zenn の 2 本の記事が、Claude Code に「やらないで」と文章で頼んでも破られた経験と、確認なしで任せる範囲・必ず人間に回す範囲の決め方を、それぞれ実例で示した。

- 1 本目：CLAUDE.md に「走っている最中のスクリプトを書き換えない」と書いたのに、6 時間の動画生成中に 2026-08-28 の同じ日に 2 回破られた。書く方法をやめ、書き換え直前に割り込む hook を 13 本（止めるものと知らせるだけのもの）に整えた。最初の判定は無関係なファイルまで止め、止めるべきものだけを止める設計は想定より難しかった。
- 2 本目：読み書き・調べもの・ローカルのテストは確認なしで任せ、お金が動く、取り消せない、外部公開、個人情報は人間に回す。パスワードは人間が環境変数に置き、エージェントは参照だけにする。SNS 投稿は公式アカウントに限り個別承認を外し、別のエージェントによる機械チェックを条件にした。

**So what**：「ルールを書く」から「機械で強制する」への移行が、個人の実践でも同じ形で出ている。承認の外し方も、機械チェックとセットで決める点が具体的。どちらも個人運用の小規模な事例で、業務への適用は条件が変わる。

## 5. Claude Code v2.1.301：自動モードの判定が OTel で追える、モデル切り替え時の要約の扱いを修正
![](https://opengraph.githubassets.com/320b6490de42374d99ccc5201a9e44d68b796444a013218ca10bea6e20c91cc9/anthropics/claude-code/releases/tag/v2.1.301)
**一言で**：Claude Code v2.1.301（10 月 15 日）で、自動モードの分類器による許可・拒否を OpenTelemetry のイベントで区別できるようになり、モデル切り替えやワークツリーまわりの不具合が直った。

- 運用：`tool_decision` イベントに `classifier_verdict`・`permission_mode` が加わり、分類器の判定とルールによる判定を区別できる。`OTEL_LOG_TOOL_DETAILS=1` のときは、ブロックの根拠になった組み込みルールを示す `classifier_category` も出る。放置運用向けに、利用上限の解除が遠いときは待たずに打ち切る設定も追加された。
- 修正：終了時に未 push のコミットがあるかもしれない WorktreeCreate フックのワークツリーを黙って消さない。Grep・Glob は検索プログラムの失敗を「該当なし」と報告しない。小さいコンテキストのモデルへ切り替えても、確認なしで要約に使用量を使わない。
- ほか：LLM ゲートウェイの背後で圧縮が繰り返される問題、フル ディスク時の誤った「/login」表示、Esc で回答が消える Vim モードの挙動などを修正した。

**So what**：許可の自動判定を、組織の監査ログに乗せやすくする変更。権限を自動化する運用をしているチームほど、判定の根拠を後から追える点が実務上効く。それ以外は不具合修正が中心で、個別の機能の大きさは限定的。
