## 3. Claude Code の窓を増やしても仕事は 1 つに集まる：役の分け方と CLAUDE.md の書き方
![](https://res.cloudinary.com/zenn/image/upload/s--nx_Dv7bp--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:Claude%2520Code%2520%25E3%2581%25AE%25E7%25AA%2593%25E3%2582%2592%25E5%25A2%2597%25E3%2582%2584%25E3%2581%2597%25E3%2581%25A6%25E3%2582%2582%25E3%2580%2581%25E4%25BB%2595%25E4%25BA%258B%25E3%2581%25AF1%25E3%2581%25A4%25E3%2581%25AE%25E7%25AA%2593%25E3%2581%25AB%25E9%259B%2586%25E3%2581%25BE%25E3%2582%258B%25E3%2580%2582%25E5%25BD%25B9%25E3%2581%25AE%25E5%2588%2586%25E3%2581%2591%25E6%2596%25B9%25E3%2581%25A8%2520CLAUDE.md%2520%25E3%2581%25AE%25E6%259B%25B8%25E3%2581%258D%25E6%2596%25B9%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:Ciel%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyLzAyZGJiOGEwYzEuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)
**一言で**：複数の Claude Code を並べて使う筆者が、役割を文書に書かないと「話が早い窓」に仕事が集まると気づき、窓ごとの CLAUDE.md の頭に書く 4 項目を整理した。

- 記事を書く窓の CLAUDE.md が 71KB に膨らんでいたが、役割を分けて渡し先を決めたところ、約 11 分で約 19KB に減った。
- 公開ボタンを押す役は 7 日間で 4 回変わった。伝言だけで変えると、受け取る窓の CLAUDE.md が古いまま残り食い違いが出たため、役割を変えるときは伝言と該当行の両方を直す。作業フォルダを窓ごとに分けると持ち主がフォルダで分かる。
- 書く 4 項目は「持つ物」「渡した物（渡し先）」「押す役（公開・送信など）」「触らない所」。2 つの窓の「持つ物」を並べて重なりを見つける。

**So what**：並列運用では、速さより「誰が最後の確認と公開を担うか」の線引きが問題になる、という個人の運用記録。再現できる書式がある一方、1 人の運用の数字で一般化はできない。

**一言で**：Claude Code のサブエージェントに親の会話の文脈が渡るかを、ランダムな合言葉で検証した記事で、`fork` 指定の子だけが合言葉を答えた。

- 親の依頼文の先頭に毎回新しい合言葉（`ZQ`+4 桁）を置き、子には「合言葉を答えてください」とだけ渡す方法。素のサブエージェント 0/5、渡すなと指示した場合 0/5、`subagent_type` に `fork` を指定 5/5（子への依頼文は同一）。
- 存在しない型の指定はエラーで子が起動せず、合言葉を明示した対照は 3/3。23 回の合計料金は約 1.39 ドルで、1 回平均は fork が約 0.049 ドル、素が約 0.066 ドル。使用版は 2.1.310。
- 筆者は「子が親の会話を知っていた」とまでは断定していない。`fork` は `claude --help` や型の一覧に出ないため特別扱いと推測する。回数が少なく、版も 1 つだけと限界も明記。

**So what**：サブエージェントに任せる際、親の文脈が漏れる／渡るかを実測で確かめた具体例。機密や無関係な文脈を子に渡したくない運用では、型の指定で挙動が変わる点を確認する材料になる。

## 7. 安い判定モデルに Opus を「困ったときだけ」呼ばせると、精度を保ったまま費用が約 4 分の 1 に
![](https://cdn.sanity.io/images/pwmfmi47/production/9a5d7191d614c824c822ec90672adaf424699d3d-2400x1256.png?w=1200)
**一言で**：Hightouch が、名寄せ（アイデンティティ解決）の結果を採点する LLM 判定器で、安価な判定モデル Jev が自信のない案件だけ Opus に回す構成を試した（11/4）。

- 合成した 1,000 件（正しい名寄せと誤結合が半々）で、易しい版は Opus 5.5 が精度 99.0%・1,000 件 3.86 ドル、GPT-6 Luna が 97.3%・0.10 ドル、Jev が 95.7%・0.05 ドル。判定モデルは応答約 0.15 秒。人手の確認は 1 時間約 50 件で、誤結合率を ±1% で推定するには 1,000 件超の確認が要る。
- Jev が先に答え、確信度 30〜90% の案件だけ Opus に回すと、易しい版で 98.8%・0.88 ドル（Opus 単独の約 4 分の 1）。難しい版は Opus 95.1%、判定モデル単独は約 89%、混成 95.3%・2.94 ドル（Opus 単独 5.39 ドル）で、費用差は約 1.8 倍に縮む。
- Jev は間違いに低い確信度が付きやすく、エスカレーションの判定が機能した。一方 Luna は誤答でも確信度が高く、混成では効きが悪かった。

**So what**：「どこまで安いモデルに任せ、どこから高いモデルや人に回すか」を、確信度の較正という指標で決める具体例。合成データでの自社ベンチマークで、実データでの再現は示されていない。

## 8. Libghostty 1.0：ターミナル描画のライブラリが安定版に、JetBrains の IDE も採用
**一言で**：Mitchell Hashimoto 氏が、Ghostty から切り出した C ライブラリ `libghostty-vt` の 1.0 を公開し、ライブラリと C ABI が安定したと宣言した（11/6）。

- JetBrains の IDE（利用者 1,250 万人超と同社が公表）の内蔵ターミナルが libghostty で動いている。Neovim では libvterm を置き換える PR が承認済みで、10 年来のスクロールバック再整形の問題も解消する見込み。KDE の試作、Vercel の Turborepo、OrbStack なども利用。
- セマンティックバージョニングと厳格な ABI 互換を約束し、不透明なハンドルと列挙キーの getter/setter で、新機能を追加しても既存のシンボルを壊さない設計。MIT ライセンスで、実行時の依存は libc のみ。
- Linux（glibc/musl）、macOS、iOS、FreeBSD、Windows、Android、WebAssembly で CI を実施。4 コア・8GB の Linux で 10,000 個の端末を同時に動かす負荷試験も行った。

**So what**：端末エミュレーションが各ツールで再実装されず共通部品に寄っていく流れ。エージェントの CLI が増える中、その土台の 1 つが安定したという位置づけ。数字は作者自身の発表。
