# 15 年使った Git から Jujutsu に乗り換えた理由

![](https://res.cloudinary.com/zenn/image/upload/s--LShNO1fJ--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:Jujutsu%2520%25E3%2581%25A8%25E5%2587%25BA%25E4%25BC%259A%25E3%2581%2584%25E3%2580%258115%2520%25E5%25B9%25B4%25E4%25BD%25BF%25E3%2581%25A3%25E3%2581%259F%2520Git%2520%25E3%2581%25AB%25E3%2582%2582%25E3%2581%2586%25E6%2588%25BB%25E3%2582%258C%25E3%2581%25AA%25E3%2581%258F%25E3%2581%25AA%25E3%2581%25A3%25E3%2581%259F%25E7%2590%2586%25E7%2594%25B1%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:oukayuka%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyL2E1MDUwMjcxNTAuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)

> [!summary] 一言で
> Git と互換性のあるバージョン管理ツール「Jujutsu」に移った開発者が、もう Git には戻れないと語る記事。

- 作業ディレクトリの状態がそのままコミットになり、add → commit の手順がいらない。バージョン管理にかかる頭の負担が減ると著者は言う。
- 変更を消しても操作ログから戻せるので、実験を気軽にできる。
- 履歴を直すときは、目的の地点に移ってファイルを書き換えるだけで、必要な rebase は自動で行われる。AI が作ったコードを何度も直す今の開発に向いているという。

> [!tip] So what
> AI と一緒に開発するのが当たり前になり、「開発者の道具そのもの」が見直され始めている兆し。
