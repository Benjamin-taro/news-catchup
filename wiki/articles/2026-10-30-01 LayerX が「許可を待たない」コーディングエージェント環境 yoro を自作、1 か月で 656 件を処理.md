# LayerX が「許可を待たない」コーディングエージェント環境 yoro を自作、1 か月で 656 件を処理

![](https://res.cloudinary.com/zenn/image/upload/s--rZa906r6--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:yoro%25E3%2581%25AB%25E3%2582%2588%25E3%2582%258D%25E3%2581%2597%25E3%2581%258F%25E3%2581%2585%25EF%25BC%2581Ai%2520Workforce%2520%25E4%25BA%258B%25E6%25A5%25AD%25E9%2583%25A8%25E3%2581%25AE%25E3%2583%25AA%25E3%2583%25A2%25E3%2583%25BC%25E3%2583%2588%25E3%2582%25B3%25E3%2583%25BC%25E3%2583%2587%25E3%2582%25A3%25E3%2583%25B3%25E3%2582%25B0%25E3%2582%25A8%25E3%2583%25BC%25E3%2582%25B8%25E3%2582%25A7%25E3%2583%25B3%25E3%2583%2588%25E7%2592%25B0%25E5%25A2%2583%2520yoro%2520%25E3%2581%25AE%25E3%2581%2594%25E7%25B4%25B9%25E4%25BB%258B%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_34:ishiken%2Cx_220%2Cy_108/bo_3px_solid_rgb:d6e3ed%2Cg_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyL2E2OTFlNjE4YzcuanBlZw==%2Cr_20%2Cw_90%2Cx_92%2Cy_102/co_rgb:6e7b85%2Cg_south_west%2Cl_text:notosansjp-medium.otf_30:LayerX%2Cx_220%2Cy_160/bo_4px_solid_white%2Cg_south_west%2Ch_50%2Cl_fetch:aHR0cHM6Ly9saDMuZ29vZ2xldXNlcmNvbnRlbnQuY29tL2EvQUNnOG9jTDlvODJfSXNnU29QZlFtMUxnVU9rLWdKNjBGbjhNMVplZzNDMEV2MFU0OTVST3NrND1zMjUwLWM=%2Cr_max%2Cw_50%2Cx_139%2Cy_84/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)

> [!summary] 一言で
> LayerX の Ai Workforce 事業部は、Claude Code や Codex を許可確認なし（YOLO）で動かす社内のリモート環境 yoro を、軽量 VM とネットワーク制限、二段構えの監視で封じ込めて運用している。

- AKS 上の Coder で 1 人 1 ワークスペースを Pod として動かし、Kata Containers の軽量 VM で隔離する。Cilium で未許可の通信を拒否し、外向きは Azure Firewall の許可リストの宛先だけに絞る。
- 2026/9/25〜10/24 の依頼は 656 件。10/12 週に PR の自動レビューを始めてから増え、週次は 9/28 週の 55 件から 10/19 週の 387 件になった。内訳は PR 自動レビュー 400 件、手元や管理 UI から 202 件、Slack の `:yoro:` スタンプ 43 件。マージは人が承認する。
- 課題も明記されている。AKS の VM 用カーネルでは VM 内の eBPF が使えず、`curl` の宛先までは追えない。GitHub や LLM API のように許可した宛先からの持ち出しや、Slack・他人の PR に紛れた指示のリスクがあるため、機密度の高い作業はまだ任せていない。

> [!tip] So what
> 業務側でも、エージェントに広い権限を渡す運用は「隔離と監視を自前で作り込む」ことを条件に成立し始めている。一方で、人間の確認が追いつかなくなる（Joe さんの例）という新しい詰まりも出ている。
