# バイブコーディング 6 週間後、Mac の起動が 20 分に。原因は Claude Code の作業ディレクトリ約 99 万ファイル

> [!summary] 一言で
> Zenn の記事が、Mac の起動が異常に遅くなった原因を調べ、Claude Code の作業用ディレクトリが `/private/tmp` に溜まっていたことを突き止めた。

- `/private/tmp` に約 99 万ファイルがあり、ほぼすべてが Claude Code の作業用ディレクトリ（リポジトリの複製と `node_modules` を含む）。プロジェクト別の内訳は約 47 万・27 万・20 万。起動時に macOS がその削除を待っていた可能性が高いとする。
- SSD の消耗は 6%（書き込み総量 251TB）だが 1 日約 600GB の書き込み。ロードアベレージは 26〜28、node の起動は毎分 1,100〜4,500 回。`.metadata_never_index` が効かず Spotlight が `node_modules` を索引していた。
- 教訓は、終わったセッションの作業ディレクトリを定期的に消す、強制終了後は診断ファイル（`forceReset-*`）を見る、など。削除対象の具体的なパスは推定で、未確認。

> [!tip] So what
> エージェントを長時間回す運用の副作用（ごみの蓄積）を実測した記録。原因は推定を含み、著者の 1 台での事例。
