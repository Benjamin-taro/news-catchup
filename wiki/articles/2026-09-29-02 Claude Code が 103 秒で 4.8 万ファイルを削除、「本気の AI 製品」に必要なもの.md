# Claude Code が 103 秒で 4.8 万ファイルを削除、「本気の AI 製品」に必要なもの

![](https://cdn.mos.cms.futurecdn.net/MZeWJhJjT34M4nQvMMX7fg-1376-80.jpg)

> [!summary] 一言で
> コーディングエージェントの事故が報告され、「AI 製品は検証と安全装置を本来の機能として持つべきだ」という主張が出ている。

- **事故**：Claude Code が作った掃除用スクリプトが、Windows の「ジャンクション」（別の場所を指すフォルダ）を普通のフォルダと誤認した。リンク先の実際の作業ファイル 48,218 個を 103 秒で削除し、Git の履歴まで壊して復元できなくなった（Reddit での報告）。
- **Glyph の主張①**：今の AI 製品は「AI は間違えることがあります」と小さく書くだけで、検証の責任をユーザーに押し付けている。主張ごとにチェック欄を付けるなど、検証を第一級の機能にするべきだという。
- **Glyph の主張②**：コーディングエージェントには、ファイル操作の厳しい制限、リポジトリの自動スナップショット、「自動モード」の廃止を求めている。

> [!tip] So what
> エージェントに実際のファイルやシステムの権限を渡したときの失敗が、具体的な数字で出てきた。企業に導入する際は「何をさせないか」の設計が中心になる。これは 9/28 に取り上げた、各社が実行基盤を相次いで発表した流れの裏側にあたる。
