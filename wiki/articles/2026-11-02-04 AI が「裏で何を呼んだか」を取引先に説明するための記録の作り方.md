# AI が「裏で何を呼んだか」を取引先に説明するための記録の作り方

![](https://res.cloudinary.com/zenn/image/upload/s--sNSb9wNW--/c_fit%2Cg_north_west%2Cl_text:notosansjp-medium.otf_55:serverToolUse%25E3%2581%25A7AI%25E3%2581%258C%25E8%25A3%258F%25E3%2581%25A7%25E4%25BD%2595%25E3%2582%2592%25E5%2591%25BC%25E3%2582%2593%25E3%2581%25A0%25E3%2581%258B%25E3%2582%2592%25E6%258A%258A%25E6%258F%25A1%25E3%2581%2599%25E3%2582%258B%2520%25E2%2580%2594%2520%25E5%258F%2596%25E5%25BC%2595%25E5%2585%2588%25E3%2581%25AB%25E8%25AA%25AC%25E6%2598%258E%25E3%2581%25A7%25E3%2581%258D%25E3%2582%258BAI%25E5%2588%25A9%25E7%2594%25A8%25E3%2583%25AD%25E3%2582%25B0%25E3%2581%25AE%25E4%25BD%259C%25E3%2582%258A%25E6%2596%25B9%2Cw_1010%2Cx_90%2Cy_100/g_south_west%2Cl_text:notosansjp-medium.otf_37:JOINCLASS%2Cx_203%2Cy_121/g_south_west%2Ch_90%2Cl_fetch:aHR0cHM6Ly9zdGF0aWMuemVubi5zdHVkaW8vdXNlci11cGxvYWQvYXZhdGFyL2NhOWUwY2FiYmYuanBlZw==%2Cr_max%2Cw_90%2Cx_87%2Cy_95/v1627283836/default/og-base-w1200-v2.png?_a=BACMTiAE)

> [!summary] 一言で
> Claude Code のヘッドレス実行で、JSON 出力の `usage.server_tool_use` から Web 検索・Web フェッチの回数をジョブごとに記録し、取引先に「外部検索をしていない」と示す仕組みを作った Zenn の記事。

- 営業メールを確認なしで自動送信して失敗した経験から、draft → 承認 → 実行の順にした。承認時に見えるのは出力だけで、AI が外部にアクセスしたかは分からなかった。
- キーの欠落と 0 回を区別するため、欠落は `unknown` に数える。`unknown` が 0 件のときだけ「記録はない」と言える、と先に線引きした。顧客データのジョブには `--disallowedTools "WebSearch,WebFetch"` も付け、設定とログの両方で 0 を確認する。
- Bash の `curl` や MCP 経由の通信はこのログに出ないため、別に `--allowedTools` での制限や Hooks が要る。

> [!tip] So what
> 業務側では、エージェントに任せる範囲を「禁止＋記録」で説明できる形にすることが求められている実例。個人開発の自由度とは別の線引きの仕方が見える（Q7）。
