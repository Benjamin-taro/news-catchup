# Web メール開発を変える JMAP。IMAP で 4 往復の処理が 1 回に

![](https://files.speakerdeck.com/presentations/34fdb086664c4af3b97c5694903700fa/slide_0.jpg?41470359)

> [!summary] 一言で
> speakerdeck の発表が、メールを JSON と HTTP で扱う JMAP が、ブラウザから使う Web メール開発をどう簡単にするかを整理した。

- IMAP は 1988 年の RFC 1064 が起源で、ブラウザは TCP を直接話せずバックエンドが要る。JMAP は 2019 年に RFC 8620・8621 で標準化され、HTTP API と WebSocket（RFC 8887）で直接操作できる。
- メールが JSON で返るので独自パーサーが不要になり、back-references で前の結果を次の呼び出しに渡せるため、ラウンドトリップの例は IMAP の 4 回が JMAP の 1 回になる。IndexedDB でのオフライン対応もしやすい。
- Thread 単位で取得できるため、返信案・要約・セマンティック検索の実装例（さくらの AI Engine 上の gpt-oss-120b）も示された。性能ベンチマークはなく、UI は開発中。

> [!tip] So what
> 古いプロトコルの上に作る苦労が、新しい標準でどこまで減るかの具体例。実測の改善値は示されていない。
