# Microsoft が警告：コーディングエージェントの「デバイスコード認証」を悪用すると、1 回の承認で会話履歴や私有リポジトリまで届く

![](https://www.microsoft.com/en-us/security/blog/wp-content/uploads/2026/03/MS_Actional-Insights_Phishing-social-engineering.jpg)

> [!summary] 一言で
> Microsoft のセキュリティ研究チームが、GitHub Copilot CLI を例に、攻撃者が始めたデバイスコード認証をユーザーが承認すると何が起きうるかを検証した。

- 承認ページは本物の GitHub なのでドメインでは見分けられない。承認後に起こりうるのは、リモート操作によるエージェントへのコマンド実行、`/memory` への偽の記憶の書き込み、クラウド同期された過去セッションの閲覧、`repo` などのスコープによる私有リポジトリへのアクセスの 4 つ。
- これらは管理された検証環境での結果で、実際の攻撃での確認はないと明記している。
- 対策は、自分で始めた認証以外ではコードを入れない、Safe Links の有効化、「セッションをクラウドに保存」の設定見直し、OAuth 認可の棚卸し、Copilot Memory の掃除など。Defender XDR の検知ルールも紹介している。

> [!tip] So what
> エージェントに持たせる権限（セッション・記憶・リポジトリ）が、そのまま乗っ取られたときの被害範囲になる。個別製品の話だが、承認の仕組みの設計を考える材料。
