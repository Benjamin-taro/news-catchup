# 「ソフトウェアが遅いのは言語ではなく設計のせい」。AI に言語の書き換えをさせても、多くのプログラムは速くならない

> [!summary] 一言で
> Sean Goedecke 氏が、遅さの主因は I/O 待ちと設計であり、AI には言語の書き換えでなく処理量を減らす再設計を任せるべきだと論じた。

- 実際のプログラムは DB・外部 API・ディスク待ちが中心で、CRUD の Web アプリではリクエスト時間の約半分が DB クエリのこともあり、C にしても最大約 2 倍にとどまる。
- 有効な再設計の例は、外部 API のキャッシュ化、重い処理の非同期化、逐次処理の並列化、N+1 クエリの 1 本化、必要なデータだけの取得。C 版を Rust に素直に書き直して約 30% 速くなった事例も、要因は言語でなく B 木というデータ構造の選択だった。
- ブラウザのレイアウトエンジンや 3D 描画のような CPU 依存の領域では言語変更の効果が大きいが、全体のごく一部だという立場。

> [!tip] So what
> コードを書く作業が AI に移るほど、「どこを直すと効くか」を見極める設計の目が価値になる、という議論の一例。意見記事であり、数字は一般論と事例の引用が中心。
