# バイブコーディングで機能を継ぎ足すと、Claude Code は「周辺しか読まない」ため画面ごとに数字がずれる

> [!summary] 一言で
> Zenn の uguisu_blog が、業務アプリを AI で継ぎ足して作る中で見えた Claude Code の実装のクセと、全体整合性を保つ仕組みをまとめた。

- クセは、依頼された画面の周辺しか読まない、セッションをまたぐと書かれていない決定を忘れる、CLAUDE.md の規則も読む量が多いと無視する、フロントは分割ルールを守らず 1 ファイル 2,000 行超を書く、など。
- 実際の食い違いは、受注金額の入力口が 2 つになり画面ごとに数字がずれる、税抜から税込への変更で請求だけ漏れる、ページ構成の変更で並び替え機能が消える、など。テストは通っており CI は緑のままだった。
- 対策は、概念ごとに正の置き場・単位を一か所で定義する台帳と用語集、画面一覧、型とフックによる一本化、lint での強制、全体整合性を含む受入条件を書いたチケット。筆者は人間が要件・概念・構造を先に整える PM 的な役割を担うと結論づける。

> [!tip] So what
> 「書いてもらったコードを人間が扱いやすく構造化する」役割が残る、という見方に具体例を足す記事。個人の開発での観察で、第三者の測定ではない。
