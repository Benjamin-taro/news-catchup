## 現状のまとめ
- 共用基盤・単一サービスの停止が、国内外で社会に響いた。11/12〜13 の Microsoft 365 障害は Exchange Online から約 20 サービスに広がり、国内では政府共通の業務環境を含む 37 組織が公表した（piyolog 集計）。Microsoft は、以前のネットワーク容量増強時の問題が最近のネットワーク変更で表面化したと説明し、サイバー攻撃ではないとする（[[2026-11-13-06 Microsoft 365 で大規模障害、Exchange Online から 20 サービスに波及|Microsoft 365 障害]]、[[2026-11-14-06 Microsoft 365 が約 12 時間以上の障害、Claude も認証障害（いずれもサイバー攻撃ではない）|続報]]）。同じ頃 claude.ai と Claude Code でも認証障害があり、原因は公表されていない。米 FAA は 11/13 に全米の出発便を 4 時間超止め、7,000 便超が欠航した（運輸長官の説明は老朽化した管制システムのルーターの過負荷。Digest 11/14）。大学の共用基盤 JAIRO Cloud のデータ改ざんで 800 以上の機関リポジトリが 10/28 から止まり、11/9 時点で復旧は未定（Digest 11/10）。事後報告書や原因の全容は、いずれも未公表か調査待ち。
- AI ツールの設定・連携が新しい漏えい経路になった。Apiiro は公開 GitHub の `.claude/settings.local.json` 1,122 件に実際の秘密情報があり、履歴まで含めると 2,539 件と報告した（[[2026-11-11-02 Claude Code の「今後は確認しない」承認が、パスワードを公開 GitHub リポジトリへ漏らしている|承認の漏えい]]）。独 Crissy Field の調査では、Lovable 製で Supabase を使う 34,545 サイトのうち 24,664 がログインなしでデータを返し、パスポート番号や 20 万件超のチャットが読める例もあった（約 30% は漏えい率の確定値ではないと調査側が断る。[[2026-11-15-08 AI で作ったアプリから Supabase 経由の個人情報が漏れる：Lovable 製サイトの調査で、ログインなしにデータを返すサイトが 2|Lovable]]）。Notion は委託先 Fireworks AI の侵害で、Notion AI のチャット記録の一部が流出した可能性を公表した（通知まで約 1 か月、Digest 11/11）。
- 未確認の主張も流れた。Gemini が Drive のメールやファイルを人間の査読者に回しうるという GitHub 上の主張（第三者の確認なし、[[2026-11-10-14 「Gemini が Drive のファイルやメールを人間の査読者に回す」と主張する GitHub 上の検証（第三者の確認なし）|Gemini]]）、「AI が CEO の口座残高を社内 Slack に誤投稿した」という報告（提供元は認めていない、[[2026-11-13-14 「AI が CEO の銀行残高を社内 Slack に誤投稿」と海外で話題、ただし未確認|誤投稿]]）。どちらも根拠が薄く、確定事実としては扱えない。
- 安全装置どうしの相互作用が事故を作った例として、誤作動の煙感知器が空調を止め、Jane Street の NY データセンターがほぼ水没しかけた話が出た。室温は約 143.6°F でピークを迎え、人が走って電源を抜いた（[[2026-11-12-13 Jane Street の NY データセンターを、誤作動の煙感知器がほぼ水没させかけた：冷却が止まり、人が走って電源を抜いた|Jane Street]]）。AI 機材の物流では、約 1,140 万ドル相当の NVIDIA 製ハードウェアが輸送中に行方不明になったと報じられた（評価額は未確認、Digest 11/14）。
- 前週までの流れ：PHP の重大な脆弱性 2 件（CVSS 9.2、10/21 に修正版）と「15 分で大規模悪用」への反論、eMudhra の中間証明書の鍵流出、LiteLLM の PyPI 版の侵害、「お名前.com」の VPS 経由の FX 口座の不正注文と GMO の補償、Google Cloud ロンドンの障害に対する EBA の照会。

## 論点と立場
- **単一障害点とクラウド依存**：Microsoft 365 は、メール・認証を 1 社の基盤に寄せる脆さと、構成変更とヘルスチェック失敗の連鎖を見せた。Microsoft は攻撃や AI とは無関係と説明し、Claude の障害を関連づける根拠はない。FAA は新しい AI ではなく古い基盤の老朽化が原因という当局の説明で、更新予算（500 億ドル要求）の議論につながる。
- **AI で作ったアプリの責任は誰にあるか**：Lovable の利用規約はデータの扱いの責任を顧客に置き、調査側は実データを扱う前に専門家が権限を確認するよう勧める。個人開発の自由度と、公開前のセキュリティ確認の担い手の問題が重なる。
- **承認や記録が漏えい源になる**：Apiiro は、比較した 16 のエージェントのうち既定でこの形で保存するのは Claude Code だけと述べ、Anthropic は問題を認めた。検出ツールの取りこぼし（215 件）も論点。
- **委託先管理**：Notion の件は、モデル提供事業者まで含めたデータの流れが漏えい面になることと、発生から利用者への通知までの時間を示す。侵入経路と影響件数は公表されていない。
- **安全のための仕組みが別の危険を作る**：Jane Street の教訓は、物理的に切れる手段、安全装置同士の相互作用、集計した信号の有効性。エージェントの封じ込めの設計でも、止め方が別の障害を呼ばないかの確認材料になる。
- **公開前の流出と修正の遅れ（前週の論点）**：PHP は、見出しの危機感と悪用の成立条件の厳しさを分けて読む必要があった。
