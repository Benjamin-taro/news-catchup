# AI と開発者の働き方

## 現状のまとめ
- 議論の軸が「書く量」から「任せ方と確かめ方」に動いた。Harvard の分析では、エージェント導入後にコード行数が平均 +30% 増える一方でレビューは重くなった（[[2026-10-12-02 AI コーディングエージェントの導入でコード量は 30% 増えるが、レビューは重くなる。Harvard の研究|Harvard]]。「解決した課題は増えない」という見出しの部分は未確認）。Rich Hickey の「AI はツールではなく自動化」論と DHH の書き換え検証（[[2026-10-12-03 「AI はツールではなく自動化」「それでも考えるのは人間」。DHH の Rust 書き換えの検証から見える、任せきりの落とし穴|Hickey・DHH]]）に、翌日 Huahai が「検証しながら使う道具だ」と反論した（[[2026-10-13-03 「AI はツールだ。使いこなすにはスキルが要る」。Rich Hickey の「ツールではなく自動化」論への反論|反論]]）。
- 詰まる場所が周辺基盤に移った。[[Anthropic]] は 1 日のマージが 5 月の約 2,500 件から 9 月に 3 万件超となり、git から自社製の Scion へ移行した（[[2026-10-14-01 Anthropic が git をやめ、自社製のソース管理「Scion」へ移行。1 日のマージが 5 月の約 2,500 件から 9 月は|Scion]]、数字は同社の公表値）。Meta で Mononoke を設計した著者は「設計がほぼ同じ」と指摘し、先行事例の明記を求めた（Digest 10/15、Anthropic 側の反論は記事にない）。
- レビューの作り替えが製品と社内事例の両方で出た。Claude Code チームは AI が約 90% を書く状況で、リスクに応じて承認者を変え、エージェントの承認は人間に数えない運用で PR を 2 倍超、revert を 40% 以上減らしたと公表した（[[2026-10-17-01 Claude Code チームのコードレビュー：AI が約 90% を書き、PR は 2 倍超、revert は 40% 以上減|社内事例]]、自社計測）。翌日、PR を 6〜10 分でレビューする Code Review が Team・Enterprise で正式版になった（[[2026-10-18-01 Claude Code の Code Review が正式版に。Team・Enterprise の PR を 6〜10 分でレビュー、承認や|正式版]]、Zenn の週間まとめ経由で公式発表は未確認）。
- 「通った」の報告をどう信じるかも具体化した。終了コードを証拠にする書き方（[[2026-10-14-03 AI の「テストが通りました」を信じない。終了コードを証拠にする書き方|終了コード]]）、Torvalds が Claude Code に書かせたページキャッシュ改善はレビューで競合状態が見つかり、翌日に実装・テスト・カバーレター初稿まで公開された（[[2026-10-16-01 Torvalds が Claude Code に書かせたカーネル改善を公開。「指示の下で」実装・テスト・レビュー初稿まで|Torvalds]]）。PostgreSQL 19 では AI 活用のレビューで欠陥が早く見つかり、差し戻しが 8〜10 件と異例に多かった（Digest 10/14、筆者の見立て）。
- 長期の品質コストを論じる声も出た。変更コストが指数的に上がるという論考（[[2026-10-17-12 「AI の質の低いコードが増えるほど、システムの変更コストが指数的に上がる」という論考。Harvard の 718 社調査などを引く|Decoherence Trap]]、引用数字は未検証）、「AI で作って速い」を謳った Epic のランチャーを Steam の小さな更新が並んだ件（[[2026-10-16-06 Epic の「AI で作った」新ランチャーより、Steam が速くなった。公開の翌日に Valve が更新|Epic と Steam]]）。運用面では、サブエージェントの実消費が画面表示の約 22 倍だった報告（[[2026-10-12-06 Claude Code の調べもの担当（サブエージェント）のトークンを数え直したら、画面表示の約 22 倍だった|トークン]]）もあった。

## 論点と立場
- **AI は道具か、自動化か**：Hickey は、ツールは握って制御し学べるが LLM は指示なしに動く自動化で、書く過程の学びを失うと論じる。Huahai は、人が入力を決め結果を検証する点は変わらず、主導と検証の技能が論点だと返す。Sarnacki の実測では、Rust 版の通知配信率は約 14%（Elixir 版は約 60%）で、筆者は「コーディングはまだ解決していない」と結ぶ。
- **全行を読むか、意図とリスクで見るか**：Anthropic は変更の「意図」の確認とリスク別の承認へ移した。一方 Harvard の分析はレビュー時間の増加を、Decoherence Trap は変更コストの膨張を指摘する。Anthropic の数字はいずれも自社計測で、他社の環境に当てはまるかは不明。
- **AI でレビューは厳しくなるのか緩むのか**：PostgreSQL では AI レビューが欠陥の検出量を増やし、既存の基準で見ると品質が落ちたように見えたという見方がある。レビューが止まる側の話（Harvard、Scion）と対にして読める。
- **報告の信頼性をどこで担保するか**：終了コードの記事は、指示ファイルに強制力はないので、報告に命令と終了コードがなければ信じない運用にしている。Torvalds の件では、速い出力の欠陥を人のレビューが拾った。
