# AI と開発者の働き方

## 現状のまとめ
- 先週の「書く」から「確かめる」への移行が、今週は数字で裏づけられた。GitHub の AI 生成 PR は 8 か月で 9 倍になり 8 月に人間の PR を上回ったが、人間のレビューは追いついていない（[[2026-10-07-04 Pragmatic Engineer「2026 年のテック業界」。AI 生成 PR が人間の PR を上回り、コードレビューは形骸化|Pragmatic Engineer]]）。
- 品質の数字が積み上がった。精度を信頼する開発者は 31%（[[2026-10-06-04 AI コーディングツールは「普及しても信頼されない」。精度を信頼する開発者は 31%|SD Times の調査]]）、バイブコーディング製の公開アプリの 91% に脆弱性（[[2026-10-07-03 バイブコーディングで作られた公開 Web アプリの 91% に脆弱性。Microsoft とシンガポール国立大などが調査|Microsoft らの調査]]）、AI 生成コードはデバッグと障害を増やすという調査（[[2026-10-08-03 AI 生成コードはデバッグと障害を増やし、「理解の空白」を生むとの調査（InfoQ）|InfoQ]]、本文未確認）。
- 問題は個人から組織へ広がった。[[Sourcegraph]] の [[Dan Adler]] 氏は、誰も理解していないコードが大企業のレガシー基盤に流れ込んでいると警告した（[[2026-10-05-06 Sourcegraph CEO「AI エージェントが、誰も理解していないコードをレガシー基盤に流し込んでいる」|Sourcegraph]]）。
- 作る側の変化として、画面モックを先に作る要件定義（[[2026-10-08-08 要件定義を文章でやめ、AI でモックを先に作ったら認識ズレが実装前に 3 件見つかった（Qiita）|Qiita]]）や、非エンジニアが社内アプリを作る基盤（[[2026-10-09-07 社内向けの「バイブコーディング・アプリ」基盤を作る企業が増加（Pragmatic Engineer）|社内基盤]]）が出た。雇用面では、AI は大卒の雇用を奪っていないがデジタルメディアは打撃を受けているという見方（[[2026-10-05-07 ノア・スミス「AI は大卒の雇用を奪っていない。ただしデジタルメディアの仕事は打撃を受けている」|Noah Smith]]）や、[[Microsoft]] と Meta が社内の Claude 利用を絞る動き（[[2026-10-08-02 Meta と Microsoft が社内の Claude 利用を絞り込み。Microsoft は月間 AI 支出の上限を 10 万ドルから約|コスト管理]]）も出た。
- 週末には、航空の手動操縦訓練になぞらえて「AI が外れたときに引き継ぐ力」を論じる記事など、スキルの継承の議論が続いた（Digest 10/10・10/11、いずれも 👎）。

## 論点と立場
- **コードレビューは続くか**：先週の Mattis 氏の「いずれ止まる」予測に、Pragmatic Engineer が実例の数字を付けた一方、形骸化と品質低下を懸念として挙げている。SD Times の調査でも、生産性が上がったとする回答（56%）に比べ、チームの協働が良くなったとする回答は 13% にとどまる。
- **品質の責任をどこに置くか**：Sourcegraph は検索とコンパイラ出力を使う「コードグラフ」で解決できるとするが、自社製品を売る立場の発言。調査側は、検証が追いついていないことを問題にしている。
- **開発者の価値はどこに残るか**：X では「Claude Max を数十個買える給料なのに、なぜ雇うのか」という問いと、AI の出力の確認に無限の工数がかかるという声が並んだ（個人の投稿で裏付けはない）。Noah Smith は職種ごとに影響が大きく違うとし、一括りの結論に反対する。
- **コストをどう扱うか**：Microsoft は月間 AI 支出の上限を引き下げた（上限であって実支出ではないと記事は補足）。大手が自社ツールへ寄せる動きは二次報道に基づく。
