## 現状のまとめ
- 議論の軸が「書く量」から「誰がどう検査するか」に進んだ。ソフトウェアファクトリー論は、Meta・Imprint・[[Anthropic]] の数字（いずれも自社報告）を束ね、読む量が減っても壊れない検査の仕組みが仕事になると整理した（[[2026-10-20-01 「ソフトウェアファクトリー」論：書く速度が読む速度を追い越した今、読む量が減っても壊れない検査の仕組みが仕事になる|ファクトリー論]]）。[[LayerX]] は 16 営業日で 211 本の PR をマージし、コードは 1 行ずつ読まず AI の検査結果を「味見」する運用を公開した（[[2026-10-21-01 LayerX のエンジニアが 16 営業日で 211 本の PR をマージ。コードは 1 行ずつ読まず、AI の検査結果を「味見」する「監督|LayerX]]、著者の自己申告）。前週の Harvard の分析（コード量 +30%、レビューは重く）と [[Anthropic]] の Claude Code チームのリスク別承認（PR 2 倍超、revert 40% 以上減、自社計測）が、その土台になっている。
- その検査が「効いているか」を疑う記録が続いた。Claude Code に無人で push させる CI の検査一式（10 種・約 18 秒）は、人のレビューの代わりに毎回走る一方、AI が検査自体を書き換えれば通る限界を著者が明記した（[[2026-10-23-07 Claude Code に無人で記事とコードを push させる運用の「検査一式」。約 150 行・18 秒、人のレビューの代わりに毎回走る|検査一式]]）。AI コードレビューの不合格率が 51%→13% に下がったのに、3 モデル中 2 つは全件 `unknown` で、有効票 0 でも止まらない設計だった（[[2026-10-24-03 AI コードレビューの不合格率が 51%→13% に下がったのに、3 モデル中 2 つは一度も判定していなかった|不合格率]]）。公式プラグイン security-guidance は脆弱コードを止めず、サブスク認証の headless では LLM 層が黙ってスキップされた（[[2026-10-19-03 Claude Code の公式プラグイン security-guidance を 18 回実行して測定。脆弱コードは止めず、サブスク認証の|security-guidance]]、各条件 1 回ずつの実測）。
- 速度の話は「PR が増えた」と「出荷が速くなった」が別物だと示された。Pragmatic Engineer が 27 社に聞くと、1 人あたりの週間 PR 数は大きく増えたが、上場 SaaS などは「速度は変わらない」と答え、支出は 6〜7 月がピークだった（[[2026-10-21-02 27 社の AI 支出を Pragmatic Engineer が集計。PR 数は大きく増えたが、出荷速度が上がったとは限らない|27 社]]、取材ベースで匿名が多い）。人の側では、Claude Code と 1 か月伴走して疲れ果てた投稿に、作業時間は縮んでも指示・レビュー・判断の負荷は別物という声が集まった（[[2026-10-20-03 「1 か月 Claude Code と伴走して疲れ果てた」投稿に、はてブで共感と対処が集まる。作業時間は縮んでも、指示・レビュー・判断の負荷|疲れ]]）。

## 論点と立場
- **AI は道具か、自動化か**：Hickey は、ツールは握って制御し学べるが LLM は指示なしに動く自動化で、書く過程の学びを失うと論じる。Huahai は、人が入力を決め結果を検証する点は変わらず、主導と検証の技能が論点だと返す。Sarnacki の実測では、Rust 版の通知配信率は約 14%（Elixir 版は約 60%）で、筆者は「コーディングはまだ解決していない」と結ぶ。
- **全行を読むか、読まずに検査で回すか**：StrongDM は「コードを書かず読まない」規則で、エージェントが触れない外部のシナリオ検査を置く。HumanLayer の Dex Horthy は 2025 年 7 月から消灯運用を試み、数か月で行き詰まってコードレビューを戻した。[[Anthropic]] は変更を低・中・高に分けて承認を 0・1 人・2 人にした。LayerX は約 9 割を同僚が approve し、残り約 1 割だけ条件つきで人の approve を省く。数字はいずれも自社・自己申告で、定義が揃わず横並びでは比べられない。
- **AI のレビュー・検査は信じてよいか**：検査を機械に移す側（CI の検査一式、LayerX の pr-checker）と、その検査が成立していたか自体を疑う側（不合格率の記事、security-guidance）が並ぶ。後者の事例は、有効票 0 でも止まらない集約ルールや、エラーが出ないスキップなど、「動いていないことに気づけない」型。AI が検査を書き換えれば通る限界は、前者の著者自身が認めている。
- **PR が増えれば出荷が速くなるか**：CodeRabbit の集計では 1 人あたりの週間 PR 数が前年比 +113% だが、「速度は変わらない」「PR のサイズが 3 倍になった」と答える会社もある。ROI を測れているのは損益と直結するクオンツ系くらいで、残りは匿名の証言。
- **報告の信頼性をどこで担保するか**：終了コードを証拠にする書き方、Torvalds の件（速い出力の欠陥を人のレビューが拾った）に加え、今週は「違反させて確かめる」までが実装という記事が続いた。
