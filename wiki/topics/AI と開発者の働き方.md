# AI と開発者の働き方
**関係する問い**：[[Q1]]、[[Q3]]、[[Q7]]

## 現状のまとめ
- 検証・レビューの自動化が進み、詰まりが人の判断の側に移った。PostgreSQL 19 は、LLM を使ったレビューで欠陥が大量に見つかり、コミッターが修正に追われて延期された（約 40 件の不具合報告。因果は 2 人のコミッターの見方で、公式の理由は「信頼性とスケジュールの予測可能性」。[[2026-11-16-01 PostgreSQL 19 がリリース延期、背景に「LLM によるコードレビュー」で大量に見つかった欠陥|PostgreSQL 19]]）。CodeRabbit の CEO は PR 単位の人間レビューをやめてリリース単位にし、信頼された開発者は「レビュー免除リスト」でそのまま本番へ出せると語った（月約 5,000 PR、数字は自己申告で Theo は費用の見積もりに反論。[[2026-11-19-01 CodeRabbit CEO「エージェントが書くコードの人間レビューは終わった」――月 5,000 PR の「ソフトウェアファクトリー」|CodeRabbit]]）。Nadella は、コードが安くなった今のボトルネックは検証で、「批評するモデル」でも失敗するテストを消して通すことがあると述べた（[[2026-11-17-02 Nadella が Pragmatic Engineer で語る「コードが安くなった後」──ボトルネックは検証、Microsoft は初めて|Nadella]]）。前週は LinkedIn の AI 先行レビュー（採用率 63.9%）、GitHub の Rust 移植、AlphaProof Code の形式検証が出ていた。
- 検証や設計を AI の側に寄せた実例が、さらに大きくなった。Anthropic は Claude のエージェント群が理論物理の未解決問題 2 件を約 6 週間でほぼ自律で解き、二重検証と Lean での形式検証まで組み込んだと報告したが、主要な結果の確認は人間の物理学者が担った（[[2026-11-20-01 Claude がブラックホール物理の未解決問題 2 件を、ほぼ自律で解いたと Anthropic が報告|ブラックホール物理]]）。Architect Labs は AI が CPU を設計から GDS レイアウトまで自律で作ったと発表した（電力性能比 4.59 倍は自社申告で、実チップでの確認はない。[[2026-11-21-06 AI が CPU を「設計から検証、GDS レイアウトまで」自律で作ったと Architect Labs。電力性能比は比較対象の 4.59|CPU 設計]]）。DevGhost は VS Code・Ghost の一部開発者の出力が中堅の 5〜21 倍になったと推計した（記載の多さは自動付与の影響もあり、測り方は未確認。[[2026-11-17-07 VS Code・Ghost の開発者に「5〜21 倍の出力」──DevGhost がコミット履歴から推計|DevGhost]]）。
- それでも人が見つける・決める場所が、小さな検証で示された。acerola_jp の測定では、コミットを 100 行以内に収める指示は CLAUDE.md より pre-commit フックのほうが守られ、依頼と衝突したときもフックは回避されなかった（各条件 2 回ずつ。[[2026-11-16-04 Claude Code のコミットを 100 行以内に分けさせる：CLAUDE.md より pre-commit フックが効いた|コミット分割]]）。PHP 問題 433 問の照合では、検証の網から 10 問が漏れていたこと、実行では測れない質の不備（4 問・3 問）は著者が読んで見つけた（[[2026-11-16-11 Claude Code に作らせた PHP 問題 433 問を実行して照合：不一致 0、ただし 10 問が漏れていた|PHP 433 問]]）。Google の Code Health の講演は、生成コードの品質責任は開発者にあり、局所的に推論できる設計（契約・不変条件・副作用の分離）を勧める（[[2026-11-20-04 LLM 時代ほど「理解しやすさ」を設計で作れ。Google の Code Health での講演|理解しやすさ]]）。HN の人気記事は「書くのをやめるとレビューも下手になる」と主張するが、根拠は比喩と逸話で実測はない（[[2026-11-21-03 「コードを書くのをやめると、レビューも下手になる」。AI 任せで思考を手放す危険を訴える HN の人気記事|書かないとレビューも]]）。
- 役割の境目と OSS への波及。トリプルスリーは全社に Claude Code を広げ、非エンジニアの PR が 7〜9 月で 949 件（前年同期 0 件）になった（社員 25 人の 1 社の自己報告で、品質・保守の数字はない。[[2026-11-17-01 非エンジニアのPRが3か月で949件──社員25人の会社が「2週間、全開発を止めて」AI化した記録|949 件]]）。「現場の暗黙知を持つ人を減らすと障害が増える」という意見（[[2026-11-19-05 「賢くて、本気で気にかける人が要る」――銀行から航空管制まで、現場の暗黙知を AI で置き換える危うさ|暗黙知]]、因果は筆者の解釈）、Matz の「OSS は 10 年もたないかも」（攻撃側も AI を使い、守る側の人手と資金が足りない。[[2026-11-20-05 まつもとゆきひろ氏「あと 10 年もたないかも」。AI が OSS 文化の担い手を細らせる懸念|Matz]]）、Anthropic の研究者の「ほぼ全人類が永久に失業する」発言（個人の見解で雇用の数字はない。[[2026-11-20-06 Anthropic 研究者「ほぼ全人類が永久に失業する可能性が非常に高い」と発言|失業発言]]）が並んだ。
- 使い方の知見は、個人の運用の工夫に集まった。サブエージェントの並列は軽い仕事では時間 1.29 倍・費用 2.37 倍で、重い仕事（約 1 分超）で初めて時間 0.74 倍になる（Sonnet 5.5、32 回。[[2026-11-16-05 サブエージェントの並列は速いのか：32 回測ると、軽い仕事では遅く高くなった|サブエージェント]]）。AI への指示の 99% を音声にする PM（[[2026-11-16-07 「AI への指示の 99% は音声入力」の PM が語る、3 倍速で指示が長く正確になる使い方|音声入力]]）、メモリ・フック・未実施タスク表で同じ失敗を繰り返させない記録（効果は未測定。[[2026-11-18-12 Claude Code に同じ失敗を繰り返させない：メモリ 59 ファイル・フック・未実施タスク表の 3 点を使った記録|同じ失敗]]）、自分のログから認知特性を分析して Skill にする手順（[[2026-11-20-12 自分の認知特性を Claude Code に分析させて Skill にした。AI の返答の読みにくさが減った|認知特性]]）、朝 7 時半に Claude Code から iPhone に電話がかかる個人の音声エージェント（[[2026-11-22-04 朝 7 時半に Claude Code から iPhone に電話がかかる。Mac Studio 内で完結する音声エージェントを個人で自作|音声エージェント]]）。いずれも少数回か 1 人の記録。

## 論点と立場
- **全行を読むか、読まずに検査で回すか**：CodeRabbit は PR 単位の人間レビューをやめ、信頼度に応じた免除リストと TLA+ などの自己検証で回すと主張し、番組は外れ値として扱った。PostgreSQL 19 では、LLM が見つける量が増えて人の修正と判断が追いつかなくなった。LinkedIn・GitHub・henteko・Tano は AI 先行で承認と設計を人に残す（数字は自己申告）。
- **機械の検査は信じてよいか**：検証まで機械に寄せる側（Claude の物理、Architect Labs、KPMG）と、網の漏れや「止まった場面」を挙げる側（PHP 433 問、KPMG のエージェントが規制要件の突き合わせで失敗、VulnCheck、AWS Security の「マージ可能 5/76」）が並ぶ。誤った指摘を人がどれだけ見抜けるかの数字はまだない。
- **残る力は何か**：判断基準・完了条件・責任（Matz の受講メモ）、局所的に推論できる設計とレビューの観点（Google）、現場の暗黙知を知る人（violetpixel、因果は筆者の解釈）。一方で、実装経験が差別化になると見るフリーランスも、コーディング比率が下がりレビュー・ディレクションに寄る見通しを書く（FDE ノート参照）。
- **書かない人はレビューも下手になるか**：Ekrem は判断力は練習しないと衰えると論じるが、レビュー能力の低下を示す測定はない。AI にレビューを任せ、自分でコードを書くほうを選ぶ個人もいる（小山氏、愛着が理由）。
- **職種の境目は消えるか**：トリプルスリーは非エンジニアが PR を出す側に回り、ビズリーチは業務担当者がスキルを書きエンジニアが基盤を持つ。品質・保守の数字がないため、「職種の消滅」か「人数の調整」かを分ける材料にはまだならない。
- **OSS の担い手と守り**：Matz は、AI で作るコストが下がる一方、攻撃側も AI を使い守る側が圧倒的に不利になると見る。Inko の作者は AI 生成の低品質 PR を理由に GitHub から Codeberg へ移り、「AI 生成コードは OSS か CC0 に」という主張も出た（Digest 11/16。個人の判断・意見で、広がりを示す数字はない）。
- **個人と業務の自由度**：個人は音声エージェントや常時稼働で先に試す。業務側は、確認を絞る・隔離する・文書と設定で枠をつくる型を整える（AI の企業導入・AI エージェントの基盤と安全性のノート参照）。
