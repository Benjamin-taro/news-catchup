# AI の企業導入
**関係する問い**：[[Q4]]

## 現状のまとめ
- 業務側が AI に実行を任せる枠が、運用実例と製品の両方で出た。NOTA の情シス（3 人で社員 564 人）は、依頼の受付から Okta・端末・電話番号の払い出しまでを 35 本の Claude Skill にし、人が確認する場面を「社外への送信」「取り消せない操作」「方針で結果が大きく変わる判断」の 3 つに絞った（Okta を IdP にして権限付与をグループ追加で済ませ、非連携の SaaS も API で操作。効果は「誰がやっても同じ手順」で、「10 倍の生産性」は自社の申告。[[2026-11-21-02 情シス 3 人で社員 564 人を回す。運用を 35 本の Claude Skill にして「人が確認するのは 3 場面だけ」に絞った NO|NOTA]]）。Microsoft は、非プログラマが AI で作ったアプリを自社テナント内で動かす Copilot Managed Runtime を GA にした（Entra ID・アクセス制御・監査ログ、情シス向けの管理画面あり。[[2026-11-19-03 Microsoft、AI が作ったアプリを社内で安全に動かす「Copilot Managed Runtime」を GA|Managed Runtime]]）。前週は、ビズリーチが業務担当者の書いたスキルを GKE 上の隔離環境で動かす基盤、Ubie の内製エージェント基盤が出ていた。
- 判断・検証の仕事への導入は、実験の段階で止まった場面が残る。KPMG UK は FTSE 250 企業の財務諸表を 100 超の AI エージェントと従来チームで並行して調べる「Project Exponential」（開発約 4 か月）を行い、エージェントが人間チームより良い質問をした場面があった一方、規制要件と企業の文書を突き合わせるエージェントが失敗し監査人が介入した（正式な法定監査ではなく、結果は決算の承認に使われていない。最大 20 の大型監査へ広げる意向で、数千件には成熟していないとする。英 FRC は独立性と職業的懐疑心への警告を出した。[[2026-11-19-02 KPMG UK、AI エージェント 100 超で監査の実験――人間より深く掘れた場面も、止まった場面も|KPMG UK]]）。
- 金融・業務のエージェント製品は、「重要な操作は人が承認」を前提に売られている。Payhawk は Goldman Sachs Alternatives 主導のシリーズ C で 2.8 億ドルを調達し（評価額 20 億ドル）、経費・購買・支払いのエージェントを提供する。支払いなど重要な操作は人の確認を必須にし、例外だけ人に通知する設計（顧客の 77% が日常利用など数字は自社発表。Digest 11/20）。Database Hub の Database Agents は修正案を示し承認を得てから実行する（Digest 11/20）。Instacart の検索では、実運用で LLM が必要なのは約 2% のクエリで、残りはキャッシュしたタグで処理する（Digest 11/17、自社データ）。
- 銀行の AI は、今週は新しい発表がなく、前週までの形が続いている。Northern Trust は Microsoft の FDE と顧客オンボーディングのエージェントを作り（データ準備 83% 減は発表側の自己申告）、Wells Fargo は既存の Advisor Gateway に AI Teammate を載せ（自社開発かベンダー製か判断できない）、Revolut・SMFG・八十二長野・PNC は自前に寄る。今週の銀行関連は経営人事・免許・店舗戦略が中心で、内製の数字は出なかった（銀行ノート参照）。
- 外から来るエージェントへの対応と、効果の読み方は前週から動いていない。United は第三者 AI エージェントの予約を禁止し、Southwest は ChatGPT から在庫を見せる。Artificial Lawyer は Big Law の AI 発表に顧客への数字を求め、今週は Baker McKenzie が時間課金を既定にしないと述べた（法務ノート参照）。

## 論点と立場
- **自前か購入か**：Revolut・SMFG・八十二長野・PNC は自前に寄り、Northern Trust はベンダーの FDE と共同構築、法律事務所は外部基盤、NOTA は IdP と API と Skill を自社で組む。Managed Runtime は Microsoft の基盤を買って枠にする形。いずれも 1 社の自己申告か発表で、同じ軸では比べられない。
- **人の確認をどこに置くか**：NOTA は 3 場面だけ確認して残りは止めず実行させ、API の成功応答は既定で信じ、食い違えば実設定に合わせて差分を全件報告させる。Payhawk は支払いを必ず人が承認し、Database Agents は承認後に実行する。KPMG は止まった場面で監査人が介入した。「確認を減らす」と「確認を残す」の線引きが製品ごとに違う。
- **導入の単位は道具か、役割か**：NOTA は運用手順を Skill にして役割ごと任せ、Payhawk は経理・購買・出張の役割別エージェント、Northern Trust は「エージェント + 人の承認」、ビズリーチは業務担当者のスキルを単位にする。
- **効果は見えているか**：NOTA の「10 倍」は自社申告、Payhawk の削減時間（Vinted の月 188 時間）は自社発表、KPMG は実験で決算には使っていない。Northern Trust の 83% 減も自己申告で、費用や保守の数字は載らない。
- **統制は誰が持つか**：Managed Runtime は情シスの管理画面とテナント境界、NOTA は IdP のグループと API、Wells Fargo は中央の Gateway。導入文書と管理設定で枠をつくる型（前週の導入キット）もある。
- **外部エージェントを入れるか閉じるか**：United・銀行・Delta・Amazon は閉じ、Southwest・Target・参照専用の連携は開く（前週までの整理）。共通の論点は、認証情報の共有とエージェントが動かした取引の責任。
