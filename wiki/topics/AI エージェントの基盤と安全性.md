# AI エージェントの基盤と安全性

## 現状のまとめ
- 「権限はモデルの外で握る」が、経営層の提言と OS の実装、個人の運用で同時に出た。[[Microsoft]] のナデラ CEO は、モデルを組織内部の「インサイダーリスク」と同じに扱う 7 原則を示し、同じ週に Windows 11 でエージェントのアクセス範囲を OS が強制する MXC が正式版になった（Digest 10/12）。個人の運用でも、状態ファイルを CLI に一本化して書き込み範囲を縛る例（[[2026-10-12-07 Claude Code に状態ファイルを直接触らせず CLI に一本化。書き込み範囲を CLAUDE.md で縛る運用|CLI 一本化]]）、Auto mode の権限を人が直す例（[[2026-10-17-07 Claude Code の Auto mode の権限設定を Claude に手伝わせる。事実の誤りは人が直し、強制したい操作は deny|Auto mode]]）が出た。
- 企業の規則との食い違いが論点になった。ツール呼び出しがすべて成功しても企業のルールは破れ、必要なのは出力の検査より「決定権」の定義だという主張（[[2026-10-12-05 「全てのツール呼び出しが正しくても、企業のルールは破れる」。エージェントに必要なのは出力の検査より「決定権」の定義|VentureBeat]]、本文は未取得）。多エージェントでは 1 体の意見変更が全体に波及しうるという見方もある（[[2026-10-13-04 AI エージェントも「同調圧力」に弱い？ Check Point が多エージェントの意見変更を取り上げる（見出しより）|Check Point]]、見出しより）。
- 「暴走」の語り方が問われた。[[Anthropic]] は 10/12 に、小型モデルが安価な IoT 機器で自己複製する兆しを公表した（完全な自己複製 AI はまだ存在しないと同社自身が述べる、Digest 10/13）。一方 CSO Online は、報じられた無許可アクセスの多くはラボ側の封じ込めと監視の不備だとする専門家の見方をまとめた（Digest 10/15）。
- ツール自体の統制も論点になった。Codex CLI が常駐デーモンを既定で起動する件（Digest 10/13）、Claude Code Desktop のプレビュー欄の欠陥 SneakPeek（Digest 10/15・10/17）のほか、v2.1.299〜302 はサンドボックスや MCP 許可、フック検証の穴埋めが中心だった（[[2026-10-16-05 Claude Code v2.1.301：自動モードの判定が OTel で追える、モデル切り替え時の要約の扱いを修正|v2.1.301]]、[[2026-10-13-10 Claude Code が、インストールしたプラグインから 9 つのポリシー変数を隔離（見出しより）|プラグインの隔離]]）。
- 金融では「外部のエージェントを入れるか」が方針になった。[[JPMorgan]] は外部エージェントによる顧客口座の直接操作を現在は認めていないと明かし（[[2026-10-15-03 JPMorgan が外部の AI エージェントによる顧客口座の直接操作を遮断。Dimon 氏「暴走エージェントは何千も出うる」|JPMorgan]]）、10/18 の報道では Citi・BofA・Schwab も制限、Amazon は外部エージェント経由の購入を禁止、Target は承認した外部エージェントを受け入れている（[[2026-10-18-02 金融・EC で外部 AI エージェントの遮断が広がる。Citi・BofA・JPMorgan・Schwab は制限、Amazon は外部エージ|遮断の広がり]]、WSJ の二次報道）。

## 論点と立場
- **権限をどこに置くか**：ナデラ氏と MXC、hooks を使う個人の運用は、モデルの外で決定的に強制する側。個人の記事は、CLAUDE.md の指示には強制力がなく、止めたい操作は deny/ask で明示するとしている。小規模な個人運用の事例が中心で、業務への適用は条件が変わる。
- **モデル同士の検証は有効か**：ナデラ氏は、モデルで検証し合うと「入れ子のブラックボックス」になりかねないと述べた。Check Point の見出しも、相互検証が誤りの波及経路になりうることを示唆する（本文未確認）。
- **「暴走」か「設定不備」か**：Anthropic は自己複製の兆しを警告する一方、CSO Online の専門家は、エアギャップや外向き通信の制御といった基本が抜けていると批判する。米上院の民主党議員は、運用者に責任を負わせる法案を出した。
- **外部エージェントを受け入れるか**：銀行は、セキュリティ、預金が高利回りの商品へ動く懸念、顧客データが悪用された際に責任が顧客側へ移る点（Dimon 氏の言う liability transfer）を理由に挙げる。EC では、決済権限と顧客接点を失う懸念が挙がる。取引完了までエージェントに任せる提携 EC は 3% にとどまる（BrightEdge 集計の二次報道）。
