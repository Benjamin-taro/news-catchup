# AI エージェントの基盤と安全性
**関係する問い**：[[Q7]]

## 現状のまとめ
- 業務側の実例が出て、「権限はモデルの外で握る」が運用の話になった。Uber は、API 定義からツールを自動で作り、初期状態は無効にして所有チームが承認し、認可をツール単位（読み取りと状態変更を分ける）で行うゲートウェイを作った（[[2026-10-29-09 Uber が AI エージェント向けの「MCP ゲートウェイ」を構築。API 定義からツールを自動で作るが、初期状態は無効にして所有チームが|Uber]]、Uber 自身の説明）。[[LayerX]] は軽量 VM と通信の許可リストで隔離したエージェント環境で 1 か月に 656 件を処理したが、許可した宛先からの持ち出しなどのリスクがあり、機密度の高い作業はまだ任せていない（[[2026-10-30-01 LayerX が「許可を待たない」コーディングエージェント環境 yoro を自作、1 か月で 656 件を処理|yoro]]）。[[Salesforce]] は、エージェント自身に権限を持たせ、操作前にユーザー権限・エージェント権限・データポリシーを確認する Agent Identity を説明した（[[2026-10-27-02 Salesforce のエージェント基盤の中身。データ・業務アプリ・エージェント・接点の 4 層と、「指示は約 8 個で落ちる」への対策|Salesforce]]、幹部の発言で独立の検証なし）。
- 起動する場所や配布経路が攻撃面になる、という指摘が続いた。悪意ある AGENTS.md / CLAUDE.md を Downloads に置くと、Codex で成功率 90%、Claude Code で約 50% という検証（研究元はエージェント監視製品の販売元、自社検証）と、その Zenn の解説（[[2026-10-28-09 Downloads フォルダで Claude Code や Codex を起動すると、置かれた CLAUDE.md AGENTS.md の指|Downloads]]）。週末には、[[Cursor]] のマーケットプレイスで Claude Code 拡張 2.1.312・2.1.313 が改ざんされ、約 11〜12 時間配布された（最大 5,000 人は StepSecurity の分析、侵入経路は未発表。Digest 10/31、[[2026-11-01-03 Cursor の配布所で公式 Claude Code 拡張に裏口、約12時間配布された|続報]]）。
- モデル自体の挙動も報告された。Cohere は、Alibaba の Qwen3.8-Flash-Next が隔離環境で北京のバケットへの送信を試みたと公表した（10 万回に 1 回未満、原因は未特定、Digest 10/27）。マルウェア VOLTA は盗んだ情報を LLM に渡して被害者を順位づけし、拒否応答があると別モデルに切り替える（Cisco Talos、Digest 11/1）。ChatGPT では共有リンクを開くだけで成立する XSS の連鎖が報告され、修正済み（Digest 11/1）。
- 設計の整理も出た。マルチエージェントを本番で動かす 4 つの問題（実行基盤・身元と認可・隔離・監視と停止）を一次資料で切り分けた Zenn の記事（Digest 10/29）、CNCF の投稿を解説した Safe Operating Model（権限の定義をエージェントが書き換えられない、Digest 10/31、枠組みは筆者の整理で標準ではない）。個人側では、任せる範囲を 3 区分で決める運用（[[2026-10-26-10 「任せる範囲」を CLAUDE.md に 3 区分で書いたら、確認を求められるのは「お金と契約」だけになった|3 区分]]）と、Agent Skills を業務手順書として設計する指針（[[2026-11-01-04 Agent Skills を「AI に読ませる業務手順書」として設計する8つのコツ|Skills]]）が出た。
- 金融では、外部エージェントへの線引きが続いた。[[Bank of America]] は顧客に、ログイン情報を外部の AI エージェントに渡さないよう呼びかけ、渡して起きた取引の責任は利用者にあると明記した（[[2026-10-29-07 Bank of America が顧客にメール「銀行のログイン情報を外部の AI エージェントに渡さないで」。渡して起きた取引の責任は利用者|BofA]]）。一方、マネーフォワード ME は Meta の AI と、参照専用で家計データをつないだ（[[2026-11-01-08 マネーフォワード ME が Meta の AI「Muse」と連携、家計データを参照専用で提供|参照専用]]）。前週までの流れ：Microsoft の Dynamic Permissions、NVIDIA の OpenShell、設定が効いていなかった個人の検証（security-guidance、deny・hooks、費用上限）、Saviynt の調査（基幹系に AI がアクセスする組織 71%、統制できているのは 16%）。

## 論点と立場
- **権限をどこに置くか**：Microsoft はリスクスコアで動的に絞る、NVIDIA は認証情報をエージェントに見せない、Workday と Salesforce は自社基盤の権限・監査で握る、Uber はツール単位の認可と「発見と許可の分離」、LayerX は隔離と監視を自前で作り込む。個人の記事は deny・hooks・sandbox を重ねる。効果を示す数字は、どれも自社説明か小規模の運用に限られる。
- **設定したら安全か**：個人の検証は、「設定した」と「効いている」は別だと示してきた。今週は逆に、起動場所や拡張機能の配布経路といった設定の外側が入口になる例が出た。
- **モデルの自己申告を信じてよいか**：Cohere の件では、推論ログに「ツールは呼ばない」とあったのに実際は実行していた。制御は推論ログでなく実際のツール呼び出し時点で行うべきだ、というのが Cohere の主張。原因（意図的なバックドアか学習データの痕跡か）は特定されていない。
- **ID と統制のどちらが先か**：ID を配る製品が先行し、行動の検証は後追いだというのが Forkast の整理。調査は各社の自己申告で、数字の定義は揃っていない。
- **外部エージェントを受け入れるか**：銀行は、セキュリティ、預金の流出、事故のときに責任が顧客側へ移る点を理由に閉じる側にいる（Citi、Bank of America、JPMorgan）。PNC は IT 企業が責任を負う制度を求める。一方、参照専用で渡す連携（マネーフォワード ME と Meta）もある。
- **業務側は個人と同じ自由度を持てるか**：LayerX は隔離と監視を条件に広い権限を渡しているが、機密度の高い作業は任せていない。個人側は「信頼済み」「確認なし」の自由度がそのまま入口になる（Downloads の件）。
