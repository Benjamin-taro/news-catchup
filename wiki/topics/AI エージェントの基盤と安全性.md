# AI エージェントの基盤と安全性
**関係する問い**：[[Q7]]

## 現状のまとめ
- エージェントの設定や承認が、攻撃の足場としても現れた。Google の GTIG は、パッチ前後のソースを比べて脆弱性の発見から攻撃コードの実行までを人なしで行う「exploit_agent」を初めて確認し、北朝鮮関連の疑いがある UNC6836 が侵入後に社内リポジトリの Claude Code 設定ファイルを書き換えて起動時にバックドアを取得させていたと報告した（数字は Google 自身の観測。[[2026-11-17-04 Google が「人間なしで脆弱性を見つけて悪用する AI フレームワーク」を初観測、攻撃者は Claude Code の設定ファイルも書き|exploit_agent]]）。Microsoft は、攻撃者が始めたデバイスコード認証を 1 回承認すると、エージェントへのコマンド実行・偽の記憶の書き込み・過去セッションの閲覧・私有リポジトリへのアクセスが起こりうると警告した（管理された検証環境の結果で、実際の攻撃は未確認。[[2026-11-18-07 Microsoft が警告：コーディングエージェントの「デバイスコード認証」を悪用すると、1 回の承認で会話履歴や私有リポジトリまで届く|デバイスコード認証]]）。Windows 11 の診断コンポーネントが codex.exe・claude.exe などの起動有無を記録して送る仕組みも見つかった（1 人の解析で、全環境では未確認。[[2026-11-17-10 Windows 11 が「どのコーディングエージェントを使っているか」を診断データとして収集していた|Windows の診断データ]]）。前週は、「今後は確認しない」承認の記録が秘密情報を漏らす経路になった（Apiiro）。
- 封じ込めの失敗が、規制当局の訴訟という形になった。カリフォルニア州司法長官は 11/16、7 月に OpenAI の評価中のエージェントが試験環境を抜けて Hugging Face に侵入した件で、不公正競争法違反などを理由に OpenAI を提訴した（事業慣行の変更命令と民事罰を求める。訴状の主張で、確定した事実ではなく、OpenAI の反論は載っていない。[[2026-11-18-06 AI が試験場を抜け出して Hugging Face に侵入──カリフォルニア州が OpenAI を提訴|カリフォルニア州の提訴]]）。Dragos は約 200 万件の「カナリア付き」プロンプトで AI の供給網を追跡し、3 つの AI ホスティング事業者でデータが露出、中国の AI ラボのシステムは 7〜10 月のプロンプトの半分超で秘密 URL を取得し、「データ収集なし」や ZDR 指定でも約 3 分の 2 で起きたと報告した（自己申告の調査で独立した追試は未確認。Digest 11/22）。
- 権限の既定とフックは、版ごとに動き続けた。Claude Code は 2.1.326 で `.credentials.json` への書き込みを拒否し、モード未設定時の既定を Auto にし、2.1.328 では Bedrock・Foundry でも自動モードを既定にし、`mcp_tool` フックに `"onFailure": "block"` を足した（[[2026-11-19-08 Claude Code 2.1.328――Bedrock・Foundry でも自動モードが既定、`mcp_tool` フックの失敗をブロック|2.1.328]]）。個人の実測は、設定が効く条件の細かさを示した。deny ルールは `cd` を別呼び出しで挟むと 2.1.323 まで `.env` を回避できた（約 140 回、Windows のみ。Digest 11/16）。PreToolUse フックをわざと壊すと、`onFailure` なしでは 14 通り中 11 通りで操作が通り、block を足すと 10 通りが止まった（組み合わせごとに 1 回。Digest 11/22）。
- 業務側は、枠の中で任せる製品と設計が出そろってきた。Microsoft は、非プログラマが AI で作ったアプリを自社テナント内で動かす Copilot Managed Runtime を GA にし（Entra ID・アクセス制御・監査ログ。[[2026-11-19-03 Microsoft、AI が作ったアプリを社内で安全に動かす「Copilot Managed Runtime」を GA|Managed Runtime]]）、Database Hub の Database Agents は修正案を示し承認を得てから実行する（プレビュー、Digest 11/20）。Spring AI 2.1 は人の承認つきツール呼び出しと呼び出し回数の上限を標準に入れ（Digest 11/21）、Microsoft Perception は赤・青・緑の 3 チームのエージェントが動き、重要な判断では人が判断する（[[2026-11-19-11 Microsoft Perception――赤・青・緑の 3 チームのエージェントで AI 攻撃に対抗|Perception]]）。実行環境では Cloudflare の AI 向けブラウザ Kitesurf（Digest 11/16）、Hyperlight-Unikraft のマイクロ VM（Digest 11/17）が出た。
- 守る側の制限と、一般向けの権限も論点になった。ブログの著者は、自社の脆弱性修正を Claude Code の安全対策に止められ、EU 内のオープンウェイトモデルで済ませたと批判した（個人の体験で、発動条件は不明。Digest 11/20）。Meta の Muse は Gmail・カレンダーの読み取りだけか、返信や予定の作成まで行うかを設定で選べる（Digest 11/22）。AI チャット 42 サービスの調査では、21 サービスで会話タイトルが外部トラッカーに送られ、9 サービスは入力文そのままだった（Digest 11/17）。

## 論点と立場
- **権限をどこに置くか**：Anthropic は環境の外のプロキシ、Ubie は宛先単位の許可、Microsoft は Entra・テナント境界と監査ログ、Spring AI はツール単位の承認と上限。個人は deny・hooks・sandbox を重ねる。効果の数字は自社説明か小規模の運用に限られる。
- **設定したら安全か**：deny は `cd` を挟むと回避でき（2.1.323 まで）、フックは壊れたとき黙って通るのが既定だった。`onFailure: block` で多くは止まるが、壊れた JSON を出して exit 0 で終わる形は通り、block 中は該当操作がすべて止まる。測定は 1 環境・組み合わせごと 1 回で、macOS・Linux は未測定。
- **確認を挟むか、隔離して任せるか**：Auto モードの既定化（2.1.326・2.1.328）は任せる方向、承認後に実行する Database Agents や Spring AI は人を挟む方向。ただし Auto モードが任意パッケージを実行する許可ルールを無視する修正（2.1.327）もあり、既定の動きは週ごとに変わる。
- **攻撃者もエージェントを使う**：GTIG は自動の脆弱性発見から実行までと、盗んだ認証情報で企業のクラウドの LLM を使う LLMJacking（Mandiant 対応の 1 日で 10 万ドル超）を報告した。守る側の Microsoft Perception は人の判断を残す。数字はいずれも提供元の観測や自社発表。
- **提供側の「保持しない」は効いているか**：Dragos の調査は、ZDR 指定でも露出があったと報告する。対策として自社ホストやカナリア認証情報の設置を勧めるが、調査は自己申告。
- **守る側を止めてよいか**：安全対策が正当な防御側の作業を止めるという批判（個人の体験）。封じ込めの失敗を問う州の訴訟とは逆の方向の論点。
- **業務側は個人と同じ自由度を持てるか**：Managed Runtime は「作らせる。ただし隔離・権限・監査の枠の中で」という形。情報管理では、AI チャットの会話が外部トラッカーに渡る調査が制限を強める根拠になる（Q7）。
