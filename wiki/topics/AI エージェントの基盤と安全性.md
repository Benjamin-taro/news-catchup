# AI エージェントの基盤と安全性
**関係する問い**：[[Q7]]

## 現状のまとめ
- 「承認の記録」自体が漏えい経路になった。Apiiro の調査では、公開 GitHub の `.claude/settings.local.json` 10 万 4,185 件のうち 1,122 件に実際の秘密情報があり、履歴まで含めると 1,994 リポジトリで 2,539 件。「今後は確認しない」で承認したコマンドに直書きされたパスワードが、そのまま平文で保存されていた（[[2026-11-11-02 Claude Code の「今後は確認しない」承認が、パスワードを公開 GitHub リポジトリへ漏らしている|承認の漏えい]]、[[2026-11-10-03 Claude Code の「次回から確認しない」が、秘密情報を公開 GitHub に平文で漏らしていた|iTnews 版]]、数字は Apiiro の報告）。Anthropic は問題を認め、Claude Code 2.1.323 では秘密を含みそうな規則は保存せずそのセッションだけ有効にし、2.1.325 では sandbox 内の Bash も既定で許可確認を通す変更が入った（[[2026-11-15-04 Claude Code 週間まとめ（11 8〜11 14）：Fable 5.2 は入力 $8・出力 $40、sandbox 内の Bash|週間まとめ]]、個人のまとめ）。前週は、メールアドレスが User-Agent に入る件と `--allowedTools`・書き込み制限の「設定したつもり」のずれが出ていた。
- 無人で動かす前提の設計が、公式・クラウド・業務側から同時に出た。Anthropic は常時稼働エージェントの権限を「認証情報を環境の外のプロキシに持たせ、判断が要る操作は保留して人の返事で再開」と整理（[[2026-11-15-01 Anthropic が「常時稼働エージェント」の作り方を公開。イベント受信箱・タイマー・メモリ・権限・送信箱の 5 部品|常時稼働]]）。Ubie の内製基盤は、サンドボックスに認証情報を置かず、宛先のパスや GraphQL の操作単位で許可し、後戻りできる変更だけ確認なしで進める（Digest 11/12、定量の成果はなし）。AWS の Nitro Sandboxes、Google の Agent Substrate と gVisor の CNCF 寄贈、Red Hat OpenShift 5 の Agent Sandbox・MCP ゲートウェイ GA と、実行環境の隔離を基盤側が標準で出し始めた。EKS の Nitro Sandbox を実機で試した記録は、起動が中央値 3.5 秒（通常 0〜1 秒）で、公式の説明と違い Cedar policy なしの Pod にも ServiceAccount トークンが渡ったと報告する（Digest 11/15、1 人の検証）。
- 受け入れ側が門を閉じる動きも出た。United Airlines は未承認の第三者 AI エージェントによる予約を禁止し、理由に認証情報の共有、意図しない購入、手荷物の対面確認の規則を挙げた（[[2026-11-12-04 United Airlines が、外部の AI エージェントによる航空券の予約を禁止|United]]）。Southwest は逆に ChatGPT から便の在庫を見せている。銀行も外部エージェントを閉じる側にいた。
- 委託先と連携先を含む漏えいの面が広がった。Notion は、AI 基盤の委託先 Fireworks AI の侵害で Notion AI のチャット記録の一部（全ワークスペースの 1% 未満）が流出した可能性を公表し、利用者への通知まで約 1 か月かかった（Digest 11/11）。Gemini が Drive のメールやファイルを人間の査読者に回しうるという GitHub 上の主張（Digest 11/10）と、「AI が CEO の口座残高を社内 Slack に誤投稿した」という未確認の報告（[[2026-11-13-14 「AI が CEO の銀行残高を社内 Slack に誤投稿」と海外で話題、ただし未確認|誤投稿]]）は、どちらも一次確認がない。取得権限と外部送信権限を同じエージェントに持たせる危うさとして読める。
- 個人の運用と業務の導入の型が並んだ。個人は専用ユーザー・最小権限・main への直接 push 禁止・毎回の本人承認（[[2026-11-13-01 Claude Code を自宅マシンで常時動かし、Discord から操作する運用（札幌 Meetup LT）|札幌 Meetup]]）。業務は Claude Code 導入のための申請書・回答表・3 段階の管理設定が本になった（Digest 11/10）。AI の部品としては、生成せず「判定」だけを返す Gemini Decisions API（入力 100 万トークン 0.10 ドル、Google の自己申告）が出た（[[2026-11-12-07 Google の Gemini Decisions API：1 回の入力に最大 1,000 問を 150〜250 ms で判定、入力 100|Decisions API]]）。

## 論点と立場
- **権限をどこに置くか**：Anthropic は環境の外のプロキシ、Ubie は宛先単位の許可とサンドボックス内に認証情報を置かない設計、NVIDIA も認証情報を見せない、Microsoft はリスクスコア、Uber はツール単位の認可、LayerX は隔離と二段構えの監視。個人は deny・hooks・sandbox を重ねる。効果の数字は自社説明か小規模の運用に限られる。
- **設定したら安全か**：個人の検証は「設定した」と「効いている」は別だと示してきた。今週は承認の保存先（settings.local.json）そのものが漏えい源になり、Anthropic は保存しない規則を足した。検出ツールも取りこぼし、215 件は gitleaks・TruffleHog のどちらにも見つからなかった。
- **確認を挟むか、隔離して任せるか**：Ubie は後戻りできる変更なら確認なしで進める。Anthropic は判断が要る操作だけ保留する。Claude Code の既定は確認を増やす方向（sandbox 内 Bash も確認）で、動きが週ごとに変わる。強制力のない CLAUDE.md の約束（公開させない 5 行）と、できなくする仕組み（deny・pre-commit）の差も論点。
- **隔離は穴を残さないか**：Nitro Sandbox は強い隔離をうたうが、検証側はトークンの付与、監視エージェントから中が見えない点、eBPF ツールが使えない点を挙げる。数字・結果は 1 人の検証。
- **外部エージェントを受け入れるか**：United・銀行は責任と認証情報を理由に閉じ、Southwest・参照専用の連携は開く。共通の論点は、エージェントが動かした取引の責任を誰が負うか。
- **業務側は個人と同じ自由度を持てるか**：Ubie・ビズリーチは隔離を条件に業務で任せている。個人は手元で常時稼働させ、提供側の規約で突然狭まる面もある。業務側の型は文書と設定の整備（導入キット）に寄る。
