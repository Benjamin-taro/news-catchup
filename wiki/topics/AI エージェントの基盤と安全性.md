# AI エージェントの基盤と安全性
**関係する問い**：[[Q7]]

## 現状のまとめ
- エージェント自身が組み立てる外部リクエストに、個人情報が混ざる経路が見つかった。Claude Code が Web 検索などの際に User-Agent へアカウントのメールアドレスを入れて第三者サイトに送っていたと GitHub Issue で報告され、Anthropic の開発者は v2.1.317 以降で組み込みの `cc-plugin-privacy` が決定的にブロックしていると回答した。コメントでは別ヘッダーや Edit で書いたスクリプト経由なら通り抜ける可能性も指摘され、Issue は Open のまま（[[2026-11-06-02 Claude Code がアカウントのメールアドレスを外部サイトへ送っていた件|メール送信]]、Anthropic の説明はコメント上のもの）。v2.1.317 は外部送信前の確認と hooks の失敗時ブロック、v2.1.319 は権限チェックの回避の修正と確認せず拒否する設定を加えた（Digest 11/3・11/6）。
- 権限の「設定したつもり」と実際の挙動のずれを測る個人検証が続いた。`--allowedTools` は使える道具を絞らず、settings の許可があれば「読むだけ」でもシェルが動いた（Digest 11/3）。`blockWritesOutsideWorkingDirectories` は Write と Edit は止めるが Bash の echo は通った（Digest 11/8）。MCP の Elicitations は自動実行で 6/6 回 cancel、Tasks は名乗らなかった（Digest 11/8）。どれも 1 人・少数回の観測。設計の側では、AI に鍵でなく権限を渡す整理（直読み→平文の注入→ストア経由→代理実行、CloudTrail では人と AI を区別できない）が出た（Digest 11/8）。
- 業務側の運用は「禁止＋記録」「読み取り専用＋許可リスト」で出てきた。Claude Code のヘッドレス実行で `usage.server_tool_use` から Web 検索・フェッチの回数を記録し「外部検索していない」と取引先に示す仕組み（[[2026-11-02-04 AI が「裏で何を呼んだか」を取引先に説明するための記録の作り方|server_tool_use]]）、脆弱性の修正 MR は Claude、マージは必ず人で `permissions.deny` を使う運用（[[2026-11-02-05 生成 AI 時代のインフラセキュリティ：脆弱性の修正 MR は Claude、マージは必ず人|修正 MR]]）、Stock 社の毎朝のセキュリティ確認は読み取り専用・許可リストで任せ、「人が動く必要があるか」で色分けした（Digest 11/7、自己報告）。
- エージェント増加で基盤側が作り直されている。[[GitHub]] は 1 リポジトリに数千のエージェントが同時に書き込める Git ストレージを作り、社内テストで 5,000 同時・毎秒 7,200 push を処理（[[2026-11-06-05 GitHub が「数千のエージェントが同時に push する」前提で Git のストレージを作り直した|Git ストレージ]]、第三者の確認なし）。[[Anthropic]] も Scion で同様の問題に当たった（AI と開発者の働き方を参照）。攻撃側でも AI が使われた：WorkOS は AI 攻撃ツール ARTEX による社内営業アプリへの侵入を公表し（Digest 11/7）、Binance の流出は検索広告の偽 Homebrew と偽面接が発端で、社内 AI ツールが横展開に使われた（Digest 11/4）。AI で脆弱性の悪用までは約 2 週間だが、PHP2Shell の修正は 4 人で 2 か月かかった（[[2026-11-05-04 AI が古い PHP の脆弱性を 2 週間で「悪用可能」に。直すのは人が 4 人で 2 か月、IEEE Spectrum は「40 年分の技|PHP2Shell]]）。
- 配布経路の件は進展があった。Postman が開いただけで Codex・Claude Code・Cursor にプラグインと起動時の指示が入ったと報告され、Postman は 11/3 にオプトインを分かりやすくし、フックの承認と起動時の動作を見直すと回答した（Digest 11/4、データ送信の証拠なし）。前週までの流れ：Uber のツール単位の認可、[[LayerX]] の隔離と二段構えの監視、[[Salesforce]] の Agent Identity、悪意ある CLAUDE.md を Downloads に置く検証、[[Cursor]] の拡張機能の改ざん、Cohere が報告した Qwen3.8 の送信試行。

## 論点と立場
- **権限をどこに置くか**：Microsoft はリスクスコアで動的に絞る、NVIDIA は認証情報をエージェントに見せない、Workday と Salesforce は自社基盤の権限・監査で握る、Uber はツール単位の認可と「発見と許可の分離」、LayerX は隔離と監視を自前で作り込む。個人の記事は deny・hooks・sandbox を重ね、AWS は MCP 経由を条件キーで見分けて拒否する案。効果を示す数字は、どれも自社説明か小規模の運用に限られる。
- **設定したら安全か**：個人の検証は、「設定した」と「効いている」は別だと示してきた。今週も `--allowedTools`・書き込み制限・MCP の対応状況で、設定名の印象と実際の挙動がずれる例が並んだ。Write と Edit を止めても Bash が通るなど、経路ごとに塞ぐ必要がある。
- **禁止か記録か**：外部送信を決定的に止める（`cc-plugin-privacy`）か、回数を記録して後から説明する（server_tool_use）か。前者は文字列一致に頼る限界が指摘され、後者は curl や MCP 経由が記録に出ないと筆者が書く。
- **モデルの自己申告を信じてよいか**：Cohere の件では、推論ログに「ツールは呼ばない」とあったのに実際は実行していた。制御は推論ログでなく実際のツール呼び出し時点で行うべきだ、というのが Cohere の主張。「止まっています、止めてよいですか」という Claude Code の問いが誤判定だった個人の記録（Digest 11/8）も、根拠を確認する線引きの話。
- **外部エージェントを受け入れるか**：銀行は、セキュリティ、預金の流出、事故のときに責任が顧客側へ移る点を理由に閉じる側にいる（Citi、Bank of America、JPMorgan）。PNC は IT 企業が責任を負う制度を求める。一方、参照専用で渡す連携（マネーフォワード ME と Meta）もある。
- **業務側は個人と同じ自由度を持てるか**：LayerX や Stock 社は隔離・読み取り専用・許可リストを条件に任せているが、機密度の高い作業や書き込みは絞る。個人側は手元の Mac で動かし続けるなど、手元に届く自由度が選ばれる理由になる（Digest 11/6）。
