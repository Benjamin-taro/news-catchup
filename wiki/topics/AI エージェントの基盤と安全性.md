# AI エージェントの基盤と安全性
**関係する問い**：[[Q7]]

## 現状のまとめ
- 「権限はモデルの外で握る」が、製品として出そろい始めた。[[Microsoft]] は社内の自律エージェントを統制する Project Perception を拡張し、タスク単位の権限（Dynamic Permissions）、リスクに応じた段階的な制限、攻撃・検知・修復役の Guardian Agents を発表した（Digest 10/21、招待制の Limited Public Preview で効果の数字なし）。[[NVIDIA]] の OpenShell は、エージェントを隔離し、認証情報を承認済みの宛先にだけ渡す Apache 2.0 のランタイムで、バージョンは 0.1 台（Digest 10/23）。Workday は、外部のエージェントも自社の権限・承認・監査証跡の下で動かすと線を引いた（Digest 10/19、顧客の導入事例や数字は発表になし）。
- 一方で、設定した安全装置が「効いていなかった」という個人の検証が続いた。security-guidance は脆弱コードを止めず、LLM 層は黙ってスキップされた（[[2026-10-19-03 Claude Code の公式プラグイン security-guidance を 18 回実行して測定。脆弱コードは止めず、サブスク認証の|security-guidance]]）。deny だけ・hooks だけでは抜け道が残る（Digest 10/20）。費用上限が一度も効いていなかった記録（Digest 10/23）、WSL でフックが設置以来 1 度も止めていなかった記録（Digest 10/24）、PreToolUse フックが stdin と終了コードの 2 点で素通りだった記録（Digest 10/25）。auto-mode の設定を AI に下書きさせると、理由づけが実際の記録と合わなかった（[[2026-10-22-09 Claude Code の auto-mode-setup を 2 回目に実行。下書きの「理由づけ」が実際の記録と合わなかった|auto-mode-setup]]）。いずれも 1 台・1 環境の報告。
- 通説が当てはまらなかった例もある。管理画面を AI に作らせる実験では、Claude Code と Codex の 12 回すべてで管理用 API の権限チェックが入った。見落とされたのは機能の外にある入力欄の初期値（管理者のメールが 12 回中 5 回残った）だった（[[2026-10-21-07 AI に管理画面を作らせたら裏の扉も閉めるか。Claude Code と Codex で 12 回試し、12 回とも閉めた。ただし管理者のメ|管理画面]]、1 アプリ・各条件 3 回）。
- 「エージェントに ID を配る」段階は進んだが、行動を測る層が薄い。Okta・ServiceNow・Microsoft が ID 製品を出す中、Saviynt の調査では基幹系に AI がアクセスしている組織が 71% なのに、効果的に統制できているのは 16%（Digest 10/25、Forkast は AI の記者と明記、数字は調査の引用）。エージェントや LLM を束ねる基盤が標的になった例として、LiteLLM の PyPI 版 1.107.0 に認証情報窃取とバックドアが入り、Railway も環境変数の流出の可能性を公表した（Digest 10/22、両者の関連は Railway の見立て）。
- 金融では「外部のエージェントを入れるか」が経営層の発言になった。[[PNC]] の Demchak CEO は人が介在しないエージェント取引を認めないとし、Citi・Bank of America・JPMorgan は外部エージェントを遮断、Citi は KYC に倣った「Know Your Agent」の必要を語った（[[2026-10-23-01 米大手行が AI エージェントの口座アクセスを相次いで制限。背景に「3 行で 1.6 兆ドルの無利息預金」の流出懸念|米大手行の制限]]、Digest 10/25）。前週までの流れ：ナデラ CEO の 7 原則と Windows 11 の MXC の正式版、Anthropic の自己複製の兆しの公表と、封じ込めの不備だとする CSO Online の見方、SneakPeek など Claude Code Desktop の欠陥。

## 論点と立場
- **権限をどこに置くか**：Microsoft はリスクスコアで動的に絞る、NVIDIA は認証情報をエージェントに見せない、Workday は自社基盤の権限・監査で握る、個人の記事は deny・hooks・sandbox を重ねるという違いがある。どれも一般提供前か小規模運用の事例で、効果を示す数字は出ていない。
- **設定したら安全か**：今週の個人の検証は、どれも「設定した」と「効いている」は別だと示した。確認方法は共通して、止めるべき入力で実際に止まるか、通すべき入力で通るかを実測すること。検査スクリプトが同じリポジトリにある限り AI が書き換えうる、という限界は指摘されている。
- **モデル同士の検証は有効か**：ナデラ氏は、モデルで検証し合うと「入れ子のブラックボックス」になりかねないと述べた。複数モデルのレビューが全件 `unknown` で成立していなかった例（Digest 10/24）は、その懸念に近い。
- **ID と統制のどちらが先か**：ID を配る製品が先行し、行動の検証は後追いだというのが Forkast の整理。調査は各社の自己申告で、数字の定義は揃っていない。
- **「暴走」か「設定不備」か**：Anthropic は自己複製の兆しを警告する一方、CSO Online の専門家はエアギャップや外向き通信の制御といった基本が抜けていると批判する。
- **外部エージェントを受け入れるか**：銀行は、セキュリティ、預金の流出、事故のときに責任が顧客側へ移る点（Dimon 氏の liability transfer）を理由に挙げ、PNC は IT 企業が責任を負う制度を求める。EC では、決済権限と顧客接点を失う懸念が挙がる。
